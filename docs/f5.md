# F5 Bayer RAW 重建

F5 为 Speed 的单帧 Bayer RAW 和 Balanced 的四帧等曝光 Bayer RAW 重建场景线性图像，再交给 HNCS、FFCS 或 LUMIX 输出 10-bit HDR HEIF。Quality 使用独立的 Apple ProRAW 处理路径。

## 工作方式

### 拍摄与交付

| 模式 | 采集 | 重建输出 |
|---|---|---|
| Speed | 一张名义 12MP Bayer RAW | 原生尺寸，联合降噪和去马赛克 |
| Balanced | 四张等曝光名义 12MP Bayer RAW | 曲率重建，横纵各 2 倍采样 |
| Quality | 当前相机的完整 Apple ProRAW | 既有 24MP／48MP 输出策略 |

Bayer 采集使用物理主摄原生视角，固定设备变焦为 1×。测光稳定后锁定曝光、ISO、焦点和白平衡；主曝光沿用实际测光值，并限制在硬件曝光范围。四帧使用相同请求曝光和 ISO，不插入短曝光。

`F5BurstTransaction` 从冻结快照取得一帧或四帧预算。硬件 bracket 上限只决定分组，每组终结回调确认完整后才提交下一组；全部原片写入并同步后发布 `burst.json`。超时、取消、缺帧或冲突结束事务，不追加替代曝光。

每帧保存原始 DNG 和带 stride 的整数 Bayer 缓冲，以及实际曝光、ISO、方向、相机、焦点、光圈、OIS 和请求身份。重建前重新读取 DNG 并验证元数据及文件哈希。帧间 ISO、主曝光或物理配置不一致时拒绝融合，保留原片。

### 传感器解释

`F5BayerModel` 从本张 DNG 的黑白电平与 `NoiseProfile` 建立传感器模型，绑定实际相机配置、ISO 和焦点。支持的 CV 14-bit Bayer 格式存放在 UInt16 中；DNG 白电平确定有效码值精度，映射除数作用于解码区间端点，保留原生整数低位。模型记录 DNG 哈希，不授予独立校准资格。缺少噪声模型或遇到不支持的码值范围时返回错误。

`F5CurvatureRAW` 在 GPU 上完成黑电平、线性化、相对曝光与 Stage2 增益归一化。DNG 声明的坏码、坏点和坏区域通过同 CFA 邻域中位数修复，原始整数和类别掩码保留。饱和和低端删失保留实际交付中心。

参考帧为单帧本身或四张主帧中的第二张。曝光归一化使用主帧实际曝光中位数；相机白平衡在这一阶段尚未施加。

### GPU 配准与曲率重建

`CMetalF5` 以 Objective-C++ 管理 Metal 调度、预算、复用缓冲和条带 I/O。Swift 负责元数据、文件所有权及薄桥接。App 使用预编译 Metal 库；测试编译同一份着色器并关闭 fast math。`CF5` 的 CPU 数值参考和冻结算子保留，使用 `-fno-fast-math -ffp-contract=off`。

1. GPU 通过混合基数 FFT 提取 Bayer 低频灰度，建立 Gaussian 金字塔，按块匹配并进行三次逆组合位移细化。细层同时比较零位移邻域，减少粗层受移动物体影响后的误配。
2. 半密度 RGB 局部统计、噪声矩和位移变化共同生成光度可靠度，再取 5×5 局部最小值。参考帧固定可靠度为 1。Speed 使用零位移，跳过 FFT 配准。
3. 固定高度条带生成时间融合 MHC 导引、Gaussian 梯度、块均值和方差，传播插值噪声并形成运动置信度。
4. 每个 32×32 原生块完成加窗 FFT、RGB 和 Bayer 混叠的联合曲率求解及傅里叶合成。颜色先验扣除噪声，先投影协方差再按纹理方差缩放；多帧支持的低频细节按噪声归一化证据放松平滑。
5. 以 16 像素步长重叠，以窗口平方和归一化，按条带写出有符号相机线性 RGBAf。双缓冲重叠准备与计算，每批最多 128 块，GPU 不分配整幅输出图。

配准临时缓冲在融合前释放，整数上传在归一化后释放。C++ 分配与借用缓冲在 Swift 预算中保持完整生命周期。`quality.json` 保存真实帧数、可靠度对应的原生融合／参考帧类别、删失比例和排除帧；曲率路径不写样条优化目标、收敛或条件秩结论。

### 镜头、曝光与色彩

`F5CurvatureOutput` 用有界源矩形读取相机图像，Metal 按原顺序执行 DNG Stage3 增益和镜头几何，再应用 DefaultCrop 与相机矩阵。只有增益时整行处理；几何变换先由 GPU 计算取样范围，源矩形缓冲上限为 16MiB。

`F5ColorBridge` 使用参考 DNG 的 ColorMatrix、AnalogBalance、匹配签名的 CameraCalibration、拍摄白点及可用 ForwardMatrix，建立相机 RGB → XYZ D50 → 扩展线性 sRGB。矩阵拥有一次传感器白平衡和一次 DNG `BaselineExposure`；保留负值与高于 1 的线性值。保存的 `linear-camera.f32` 位于矩阵之前，未施加白平衡或基准曝光。

重建的 GPU 配准／曲率资源在后续镜头和颜色操作之前释放，完整重建的 autorelease pool 在归档及调色之前排空。线性文件通过 C++ `pread` 按 512×64 像素供给 Core Image，保留浮点精度与方向。

`F5LinearImage` 将线性 sRGB、完整拍摄白点 xy、实际 ISO、`BaselineSharpness`、方向及照片元数据交给 `ImagePipeline.writeLinearHEIF`。颜色处理不再解码 RAW。HNCS 的虚拟相机白平衡仍使用照片白点；LUMIX 从本张照片绑定源 ISO。用户曝光在线性 RGB 上单独施加一次，再执行 HNCS、FFCS 或 LUMIX 和空间效果，编码 BT.2020/PQ 10-bit HEIF。

成片来源记录保存实际输入帧哈希和曝光、参考帧、模型与变换哈希、白平衡归属和处理状态。Speed／Balanced 的质量选择与配方一起冻结，不套用 Quality 的输出重采样策略。

### 调色前文件与测试记录

日常 Balanced 与 Quality 快门冻结一个 `rawArchiveID`。Balanced 完成合成后，先在 `RAWCaptures/<ID>/balanced/` 写入 `balanced-camera.dng`、`balanced-linear.tiff`、颜色变换及源元数据；Quality 在进入颜色处理前，将原始字节复制到同组的 `quality/original-proraw.dng`。品牌色彩、用户曝光与空间效果不写入这些调色前文件，调色成片照常进入相册。

合成 DNG 是三个相机颜色平面的 32 位浮点 LinearRaw，携带原拍摄白点、颜色矩阵、基准曝光、方向、实际 ISO 与曝光时间，黑白电平分别为三个通道的 0 和 1。文件已完成镜头处理，省略原始 opcode，防止再次应用。线性 TIFF 保存实际交给颜色引擎的扩展线性 sRGB 数值，以线性 sRGB ICC 标识；两份文件均保留有符号值和 HDR 范围。

`CaptureRAWStore` 先写临时目录，文件同步并记录哈希后再发布 `archive.json`；同身份重试验证并复用文件，来源冲突拒绝覆盖。原始文件存储与相册交付独立，调色失败仍保留已发布文件。

设置页的「记录 11 张 RAW 素材」使用 `probe` 事务，在主摄原生视角锁定曝光、ISO、焦点与白平衡，按硬件上限分组记录十一张等曝光 Bayer DNG、整数缓冲与元数据到 `F5Samples`，供离线选帧。

「记录当前场景 · Balanced + ProRAW」使用同一个归档 ID，依次完成 Balanced 四帧采集、合成与原片归档，再采集并归档 Quality ProRAW 原始字节。测试不调用品牌调色、HEIF 编码、回看或 Photos，也不请求相册权限。Bayer 输入先保存到同组的 `bayer-inputs/<事务 ID>/`；合成或归档失败时保留输入，成功后按原片保留开关决定是否清理。任一步失败后停止下一次采集；两次使用各自的实际曝光和白点，整个测试期间禁止重复启动测试或普通快门。

### 恢复与归档

`F5CaptureFormat` 实现格式载荷、来源编解码、复制、校验、恢复和渲染。已提交输入复制到待完成照片的 `burst/`，发布拍摄记录后清理重复暂存。中断或损坏输入保留原文件，用户明确放弃后清理。

系统照片图库确认保存，且冻结快照开启 `archiveF5RAW` 时，原片归档到 Documents 的 `F5Archives`。归档包含实际的一张或四张 DNG、整数缓冲、manifest、质量与颜色记录；按拍摄 ID 重复调用复用相同归档。

## 数据与版本

处理构建为 `f5-curvature-v1`，事件解码为 `f5-effective-v2`，成片色彩桥为 `f5-dng-linear-d50-baseline-v2`。格式标识为 `f5`，拍摄记录 schema 为 2；快照可用 `rawArchiveID` 关联调色前文件；`burst.json` 使用 `f5-burst-v1`，记录实际帧数。`intent.json` 保存冻结快照和已接收帧；`quality.json`、`color-transform.json`、`linear-camera.f32`、`linear-camera.json` 保存重建、色彩与相机图像布局。

`GlassCam/F5Staging` 保存活动 RAW 事务，`GlassCam/PendingCapture` 保存待完成照片，`F5Archives` 保存用户选择保留的原片。路径、字节数和 SHA-256 随文件描述保存，读取时验证所属目录边界。既有五帧参考素材使用四张主曝光重建，参考数值模块仍保留短帧似然测试。

## 已知限制

- Speed 和 Balanced 采集仅使用物理主摄原生视角，Quality 保留原有镜头和构图选择。
- 噪声来自 DNG 元数据及共同逐相位模型，空间增益后的噪声近似使用该共同模型。
- 四帧等曝光不提供额外短曝光高光；有效细节取决于位移、噪声、运动与局部可靠度。
- FFT 尺寸的质因数限于 2、3、5、7。
- 不支持 BigTIFF、三光源 DNG、Stage3 稀疏 GainMap 或支持域以外的必需 opcode 与几何变换。
- 浮点 LinearRaw DNG 的直接预览取决于 RAW 解码器，查看调色前画面可使用同目录的线性 TIFF。
- 相机硬件锁定和手机完整流程性能由设备验收覆盖。
