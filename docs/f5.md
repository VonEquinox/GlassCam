# F5 五帧 Bayer 重建

F5 从物理主摄采集五张 Bayer RAW，重建场景线性图像，再交给色彩管线生成成片。F5 模块负责连拍载荷、校准匹配、RAW 解释、重建、来源信息和原片归档；拍摄流程负责准入、重试及系统照片图库交付。

## 工作方式

### 主摄与校准

`CameraBackend.captureF5` 切到物理主摄的 Bayer 拍照会话，`F5CaptureDriver` 要求原生视角、1× 设备变焦、独立 Bayer 缓冲，以及手动曝光、锁定焦点和白平衡能力。产品拍摄匹配已导入的主摄校准包；匹配项包括硬件型号、系统构建、物理相机身份、格式签名、RAW FourCC、尺寸、CFA、ISO 和焦点范围、光圈及 OIS 策略。

校准包还包含四种 CFA 相位的噪声参数、黑电平残差、统一白尺度、原生缓冲到 DNG 码值的映射、似然描述及重建策略。导入时校验 `P0`、`G1`、`G2`、`G3`、`G4` 证据与校准、色彩验证文件的 SHA-256，并要求设备、策略和处理构建身份一致。目标设备名称是 `iPhone 18 Pro Max`；硬件型号来自校准包和运行设备。独立样本记录入口使用 `probe` 事务。

### 五帧事务与冻结配置

快门保存的 `CaptureSnapshot` 包含处理配方、输出、质量以及 `archiveF5RAW` 选择，随事务进入恢复记录。测光稳定后，驱动锁定 ISO、焦点和白平衡，记录光圈与 OIS 策略，生成 `L,L,S,L,L` 曝光序列：四张主曝光、一张短曝光，短帧索引为 2。

主曝光受自动测光、校准手持上限及纹理曝光界限约束；缺少后两者时分别采用 `1/120 s` 和测光曝光的一半，并记录不确定标志。默认短曝光为主曝光的 `1/8`，产品请求在硬件最短曝光使该比例不可实现时失败；样本入口可保留受限曝光标志。驱动使用的纳秒级 `CMTime` 精度只表示请求时间。

`F5BurstTransaction` 统一管理五帧预算。运行时 bracket 上限只决定分组，所有分组共用事务、相机配置和曝光计划；每组收到终结回调并确认帧齐全后才提交下一组，五帧全部完成后才发布 `burst.json`。超时、取消或缺帧结束事务，不追加替代曝光。

RAW 回调先保存 DNG 字节，再复制带 stride 的整数 Bayer 缓冲，随后解释元数据。文件名含载荷哈希；同一请求和序号的不同载荷分别保留。完全相同的重复帧回调去重，冲突帧拒绝进入已登记帧集合，取消后到达的载荷仍可留存。

### 交付检查与 RAW 解释

每帧记录请求与实际曝光、请求与实际 ISO、时间戳、相机身份、焦点、光圈和 OIS 策略。`F5BurstManifest.validate` 重新读取原始 DNG，与保存的元数据、尺寸、CFA、ActiveArea、方向、曝光和文件哈希核对；请求顺序和时间顺序分别保存。

实际曝光或 ISO 偏离请求超过 1% 时记录 `EXPOSURE_ADJUSTED`；帧间 ISO 偏差超过 0.1% 时记录 `ISO_CHANGED` 并阻止重建。四张主帧曝光相对其中位数偏差超过 1%、短帧不短于主帧、短帧达不到约定比例及采集跨度超过 750 ms，分别进入采集标志；主帧不均匀或采集窗口过长会阻止高分辨率尝试。物理相机、焦点、光圈或校准配置变化也会阻止重建。

`F5RAW` 读取单平面 Bayer DNG 元数据和独立整数缓冲，保留端序、行跨度、CFA 原点、黑电平、线性化以及量化区间。真实数据要求带证据哈希的 `bufferCodeMapping`；映射在区间端点上进行，原生整数低位保留。坏点从观测中排除，饱和及低端删失作为似然事件处理。

OpcodeList2 的 GainMap 进入 RAW 预测模型；OpcodeList3 的 GainMap 与几何操作按原顺序在重建后执行。未知可选 opcode 可跳过，未知必需 opcode 抛出 `UNSUPPORTED_OPCODE`。

### CPU 与 GPU 重建阶段

Swift 编排整图 Metal 重建；`CF5` 提供 CPU 配准、条件信息计算和 FP64 数值参考。App 使用预编译的默认 Metal 库，package 测试从同一份着色器源码编译并关闭 fast math；CF5 使用 `-O2 -fno-fast-math -ffp-contract=off`。

1. **准备观测。** 校验连拍与校准包，以四张主帧实际曝光的中位数归一化曝光，上传 RAW、修正表和似然参数。
2. **初始化几何。** GPU 生成引导图与清晰度统计，从主帧中按清晰度资格、距采集时间中心的距离等选择参考帧；CPU 配准保留运动候选，初始化共享运动网格。
3. **原生求解。** 共享有符号三次 B 样条系数表示颜色场，按条件块更新、粗网格校正和运动更新优化联合目标。Poisson–Gaussian 事件似然包含量化、删失及离群分量；正值约束施加在物理采样值上。
4. **检查观测资格。** 按 32×32 原生区域评估配准候选、残差、遮挡和采样信息，排除不可靠伴随帧；发生排除时重新完成原生求解，再冻结供高分辨率阶段使用的噪声尺度。
5. **尝试高分辨率。** 原生求解收敛、参考帧合格、仍有预算，且至少一个区域具备足够信息并满足残差条件时，分配横纵各 2 倍的系数网格和独立运动缓冲。高分辨率求解未收敛时保留原生结果。
6. **按区域输出。** 支持类别为 `FULL_SR`、`NATIVE_FUSION`、`REFERENCE_ONLY`、`HIGHLIGHT_MISSING` 或 `INVALID`，随质量报告保存。最终按 DNG DefaultCrop 横纵各 2 倍采样，按 64 行分条输出；原生融合与参考帧区域使用插值输出。

收敛判断同时要求目标相对变化、图像标准化梯度与运动标准化梯度满足策略阈值；每层循环上限来自校准策略。没有完成可验证原生循环时返回错误；高分辨率输出的新采样位置验证失败时，回到已经验证的原生图像。`quality.json` 保存停止原因、区域类别、排除帧和质量指标。

### 色彩桥与 HDR 成片

`F5ColorBridge` 用参考帧的 DNG 色彩矩阵、AnalogBalance、匹配签名的 CameraCalibration、拍摄白点及可用 ForwardMatrix 建立相机 RGB → XYZ D50 → 扩展线性 sRGB 的变换。白平衡由矩阵施加一次，记录 `whiteBalanceOwner = "matrix"`；色彩桥保留有符号线性值，记录统一白尺度和变换哈希。

重建后的 opcode 使用场景线性 HDR 范围策略，保留恢复出的高于 1 的高光。`F5LinearImage` 实现 `SceneLinearImage`，由通用 `ImagePipeline.writeLinearHEIF` 绑定照片白平衡与源 ISO，应用冻结处理配方的 HNCS、FFCS 或 LUMIX 色彩和效果，导出 BT.2020/PQ 10-bit HDR HEIF。

成片 EXIF `UserComment` 写入 `GlassCam F5` 来源记录：解码与色彩桥版本、五帧哈希、实际曝光、参考帧、校准与变换哈希、区域类别和停止状态。编码完成后进入通用拍摄恢复流程；系统照片图库确认保存后才记为保存成功。

### 格式注册、恢复与归档

App 将 `F5CaptureFormat` 放入不可变的 `CaptureFormats` 注册表，并注入拍摄服务与 journal。Capture 定义 `CapturePayload`、`CaptureProvenance` 和 `CaptureFormat`；F5 实现载荷、来源信息编解码、渲染、复制、校验、恢复和归档。含来源信息的记录通过注册表提供的 `decoder()` 解码。

已提交的暂存连拍复制到待完成照片的 `burst/`，校验完成后发布拍摄记录，再清理同身份、同内容的暂存副本。未提交事务在重启后报告中断并保留文件；损坏文件同样保留，用户显式放弃后才清理。借用 `F5BurstSource` 的释放不删除原片。

只有 `savedConfirmed` 且冻结快照中的 `archiveF5RAW` 为真，清理活动记录前才复制原片到 `F5Archives`；归档以拍摄 ID 命名，重复调用复用相同连拍。归档包含五帧 DNG、整数缓冲、manifest、可用校准和似然表，以及已有的质量与色彩变换记录。

## 不变量

1. 分组拍摄维持五帧序列和预算，完全相同的回调不新增帧，重复提交复用同一源对象。— `F5Tests/F5ContractTests.syntheticBurst_preservesFiveFrameRequestBudget`、`bracketLimit_preservesFiveFrameSequence`、`identicalCallback_isDeduplicatedAndCommitReusesSource`
2. 产品曝光计划在硬件最短曝光无法满足短帧比例时失败，样本计划保留受限标志。— `F5Tests/F5ContractTests.hardwareMinimumExposure_rejectsClampedProductPlan`、`clampedProbe_reportsLimitedShortExposure`
3. 合成校准包不能使真实硬件取得产品资格。— `F5Tests/F5ContractTests.syntheticProfile_cannotQualifyRealHardware`
4. 设置变化不改变已冻结照片及重试的处理配方、质量和输出。— `CaptureTests/WorkflowTests.settingsMutation_doesNotRetargetFrozenCaptureOrRetry`
5. ISO 改变保存在连拍标志中，注册后的处理入口保留 `ISO_CHANGED` 错误。— `F5Tests/F5ContractTests.changedISO_isRetainedAsEvidenceAndStopsReconstruction`、`F5Tests/registeredBurstProcessor_preservesISOFailure`
6. 奇数 ActiveArea 原点、行填充和原生码值映射保留 CFA 相位及量化区间。— `F5Tests/F5ContractTests.oddActiveArea_keepsCFAOriginAtPixelCenter`、`paddedMosaic_keepsQuantizationInterval`、`F5NumericalTests.nativeCodeMapping_keepsLowBitsAndQuantization`
7. 未知必需 opcode 被拒绝，坏传感器码从观测中排除。— `F5Tests/F5DecoderTests.unknownMandatoryOpcode_isRejected`、`badSensorCode_isExcludedWithoutRepair`
8. Stage3 操作按原顺序执行，高光扩展保留高于 1 的值。— `F5Tests/F5OpcodeTests.gainAndGeometry_preserveOpcodeOrder`、`sceneHDR_extensionKeepsRecoveredHighlights`、`stage3Operations_doNotAlsoEnterRAWPrediction`
9. 色彩桥拥有白平衡并保留有符号线性颜色，原生码值映射的除数不重复进入颜色缩放。— `F5Tests/F5ContractTests.colorBridge_ownsWhiteBalanceAndKeepsSignedLinearValues`、`F5NumericalTests.nativeCodeScale_doesNotReapplyDNGDivisorToColor`
10. Metal 样条、导数与删失似然符合独立数值参考，冻结算子保持约定误差界限。— `F5Tests/F5MetalTests.splineSample_matchesFP64ValueAndDerivatives`、`censoredAndNarrowEvents_matchExactPoissonGaussianLikelihood`、`FrozenOperatorTests.frozenGPUOperator_preservesIndependentReference`
11. 可行步降低独立目标，取消时保留图像，短帧配准歧义保留可靠主帧观测。— `F5Tests/FrozenOperatorTests.feasibleStep_reducesIndependentObjective`、`cancelledFeasibleStep_preservesImage`、`ambiguousShortFrame_keepsReliableMainObservations`
12. 重建遵守每层循环上限，声明收敛时要求运动驻点条件。— `F5Tests/F5PipelineTests.reconstruction_respectsPerLevelCycleLimit`、`convergedEpoch_requiresJointMotionStationarity`
13. 重建输出采用双密度尺寸并保留五帧来源，最终 HEIF 为 10-bit 且保留 F5 元数据。— `F5Tests/F5PipelineTests.reconstructedBurst_usesDoubleDensityAndRetainsProvenance`、`finalHEIF_isTenBitAndRetainsF5Metadata`
14. 取消后迟到的冲突载荷不会覆盖已保存的原始字节。— `F5Tests/F5PipelineTests.lateConflictingDelivery_doesNotOverwriteOriginal`
15. 拍摄记录、连拍 manifest、意图和校准包解码再编码保持固定 fixture 字节；旧 Speed 保留既有规范化规则。— `F5Tests/currentJournal_decodeEncodePreservesBytes`、`F5Tests/burstManifest_decodeEncodePreservesFiveFrameBytes`、`F5Tests/burstIntent_decodeEncodePreservesBytes`、`F5Tests/burstProfile_decodeEncodePreservesBytes`、`F5Tests/legacySpeed_decodeRetainsQualityAndExistingNormalization`
16. 已提交暂存可恢复并清理重复副本，中断或损坏连拍保留原文件。— `F5Tests/committedStaging_loadRecoversAndRemovesDuplicate`、`F5Tests/interruptedStaging_loadRetainsFilesWithOriginalFailure`、`F5Tests/corruptBurst_loadRetainsFilesAndOriginalFailure`

| 连拍 manifest | `burst.json`，`f5-burst-v1` | 五帧身份、原始文件描述、请求与时间顺序、实际曝光、采集标志、校准包及构图 |
| 事务意图 | `intent.json` | 冻结快照、用途、帧与已接收载荷、错误及 `collecting/committed/failed/cancelled` 状态 |
| 校准与策略 | `profile.json`，`1.0`；`f5-policy-v1` | 物理相机身份、适用范围、噪声模型、码值映射、证据哈希和资源预算 |
| 处理版本 | `f5-effective-v2.0.1`；解码 `f5-effective-v2` | 真实校准包与处理构建及解码版本绑定 |
| 色彩与 opcode | `f5-dng-linear-d50-v1`；`f5-scene-linear-unclipped-v1` | 色彩桥身份与场景线性高光范围策略 |
| 似然描述 | `f5-pg-v1` | 可选查找表、文件哈希、精确模型范围及近似误差界限 |
| 重建记录 | `quality.json`、`color-transform.json`、`linear-camera.f32`、`linear-camera.json` | 求解结果、变换和白平衡归属、相机线性浮点图与布局描述 |

Application Support 下的 `GlassCam/F5Staging` 保存产品事务，`GlassCam/PendingCapture` 保存待完成照片，`GlassCam/F5Profiles` 保存校准包；Documents 下的 `F5Samples` 保存样本，`F5Archives` 保存用户选择保留的原片。文件描述同时记录相对路径、字节数和 SHA-256，读取时检查路径不能逃出所属目录。

旧记录缺少 `requestedISO` 时保持未知；旧快照缺少 `archiveF5RAW` 时恢复为 `false`。字节兼容基线与来源见 [journal fixtures](../tests/fixtures/journal/README.md)。

## 已知限制

- 产品采集仅支持匹配校准包的物理主摄原生视角，其他物理镜头与数字变焦不在此入口的适用范围。
- 真实传感器曝光、焦点和白平衡锁定依赖 AVFoundation 与设备交付，自动测试未覆盖相机硬件的完整行为。
- 横纵各 2 倍的成片尺寸包含原生融合和参考帧的插值区域，有效细节受采样分布、运动、噪声与收敛条件限制。
- 解码器不支持 BigTIFF、三光源 DNG 配置、Stage3 稀疏 GainMap 及支持域以外的必需 opcode 或几何变换。
- 处理需要 Metal；预算不足、数值停滞或无有效原生结果时可能只能输出原生融合或返回错误。
- 局部颜色引导、细节初始化、局部可行步与梯度备用步等开发选项未接入产品默认重建组合。
- 实拍放大观感、完整超分恢复和手机全流程性能需要独立的设备与图像质量验收。
