# F5 Bayer RAW 重建

F5 为 Speed 的单帧 Bayer RAW 和 Balanced 的四帧等曝光 Bayer RAW 重建场景线性图像，再交给 HNCS、FFCS 或 LUMIX 输出 10-bit HDR HEIF。拍摄界面只提供这两种模式，默认 Balanced。

## 工作方式

### 拍摄与交付

| 模式 | 采集 | 重建输出 |
|---|---|---|
| Speed | 一张名义 12MP Bayer RAW | 联合降噪和去马赛克，成片放大至 24MP |
| Balanced | 四张等曝光名义 12MP Bayer RAW | 曲率重建，横纵各 2 倍采样后缩至 24MP |

Bayer 采集使用物理主摄原生视角，固定设备变焦为 1×。采集继承点选焦点、相机曝光补偿与显式 AE/AF 锁；未锁定时等待测光稳定，再锁定曝光、ISO、焦点和白平衡。四帧使用相同请求曝光和 ISO，不插入短曝光；物理拍摄方向在快门预约时冻结。

`F5BurstTransaction` 从冻结快照取得一帧或四帧预算。硬件 bracket 上限只决定分组，每组终结回调确认完整后才提交下一组；全部原片写入并同步后发布 `burst.json`。超时、取消、缺帧或冲突结束事务，不追加替代曝光。

每帧保存原始 DNG 和带 stride 的整数 Bayer 缓冲，以及实际曝光、ISO、方向、相机、焦点、光圈、OIS 和请求身份。发布采集结果或打开已有 bundle 时校验 DNG 元数据及文件哈希，后续保留与重建复用 `F5BurstSource` 持有的已校验信息。帧间 ISO、主曝光或物理配置不一致时拒绝融合，保留原片。

### 传感器解释

`F5BayerModel` 从本张 DNG 的黑白电平与 `NoiseProfile` 建立传感器模型，绑定实际相机配置、ISO 和焦点。支持的 CV 14-bit Bayer 格式存放在 UInt16 中；DNG 白电平确定有效码值精度，映射除数作用于解码区间端点，保留原生整数低位。模型记录 DNG 哈希，不授予独立校准资格。缺少噪声模型或遇到不支持的码值范围时返回错误。

`F5CurvatureRAW` 在 GPU 上完成黑电平、线性化、相对曝光与 Stage2 增益归一化。DNG 声明的坏码、坏点和坏区域通过同 CFA 邻域中位数修复，原始整数和类别掩码保留。饱和和低端删失保留实际交付中心，类别用于质量统计；当前曲率求解使用样本值与光度可靠度。

参考帧为单帧本身或四张主帧中的第二张。曝光归一化使用主帧实际曝光中位数；相机白平衡在这一阶段尚未施加。

### GPU 配准与曲率重建

生产 `F5` 只调用 `CMetalF5`，由 Objective-C++ 管理 Metal 调度、预算、复用缓冲和条带 I/O；Swift 负责元数据、所有权与桥接。App 使用预编译库，SwiftPM 测试编译同一份 F5 源码，采用 safe／precise 数学选项。曲率与配准由 `F5Tests` 的解析信号合成测试约束，镜头操作由冻结的[参考数据](../tests/fixtures/f5-post-operations/README.md)约束。

`CF5` 保留早期样条模型的纯 CPU 算子与优化自检，使用 `-fno-fast-math -ffp-contract=off`；它不参与生产路径，无图像 golden，验收入口为 `f5_core_tests`。旧样条 GPU 与探索性验证在研究仓库；文件级契约见 [ADR 0017](adr/0017-native-and-metal-contracts.md)。

1. GPU 通过混合基数 FFT 提取 Bayer 低频灰度，建立 Gaussian 金字塔，按块匹配并进行三次逆组合位移细化。细层同时比较零位移邻域，减少粗层受移动物体影响后的误配。
2. 半密度 RGB 局部统计、噪声矩和位移变化共同生成光度可靠度，再取 5×5 局部最小值。参考帧固定可靠度为 1。Speed 使用零位移，跳过 FFT 配准。
3. 固定高度条带生成时间融合 MHC 导引、Gaussian 梯度、块均值和方差，传播插值噪声并形成运动权重。传感器边界采用周期 `2n−2` 的反射，保持 Bayer 相位与角落颜色。
4. 每个 32×32 原生块完成加窗 FFT、RGB 和 Bayer 混叠的联合曲率求解及傅里叶合成。颜色先验扣除噪声，先投影协方差再按纹理方差缩放；多帧支持的低频细节按噪声归一化证据放松平滑。
5. 以 16 像素步长重叠，以窗口平方和归一化，按条带写出有符号相机线性 RGBAf。双缓冲重叠准备与计算，每批最多 128 块，GPU 不分配整幅输出图。

配准临时缓冲在融合前释放，整数上传在归一化后释放。C++ 分配与借用缓冲在 Swift 预算中保持完整生命周期。`quality.json` 保存真实帧数、可靠度对应的原生融合／参考帧类别、删失比例和排除帧；曲率路径不写样条优化目标、收敛或条件秩结论。

### 镜头、曝光与色彩

`F5CurvatureOutput` 用有界源矩形读取相机图像，Metal 按原顺序执行 DNG Stage3 增益和镜头几何，再应用 DefaultCrop 与相机矩阵。只有增益时整行处理；几何变换先由 GPU 计算取样范围，源矩形缓冲上限为 16MiB。输出及归档按设备号与 inode 拒绝源／目的文件别名；配准句柄每次构造仅执行一次，取消后由上层重新创建。

`F5ColorBridge` 使用参考 DNG 的 ColorMatrix、AnalogBalance、匹配签名的 CameraCalibration、拍摄白点及可用 ForwardMatrix，建立相机 RGB → XYZ D50 → 扩展线性 sRGB。矩阵拥有一次传感器白平衡和一次 DNG `BaselineExposure`；保留负值与高于 1 的线性值。保存的 `linear-camera.f32` 位于矩阵之前，未施加白平衡或基准曝光。

重建的 GPU 配准／曲率资源在后续镜头和颜色操作之前释放，完整重建的 autorelease pool 在归档及调色之前排空。仅在需要调色前原片归档时写出 `linear-camera.f32`；线性文件通过 C++ `pread` 按 256×256 像素供给 Core Image，保留浮点精度与方向。

`F5LinearImage` 将线性 sRGB、完整拍摄白点 xy、实际 ISO、`BaselineSharpness`、方向及照片元数据交给 `ImagePipeline.writeLinearHEIF`。颜色处理不再解码 RAW。HNCS 的虚拟相机白平衡仍使用照片白点；LUMIX 从本张照片绑定源 ISO。用户曝光在线性 RGB 上单独施加一次，再执行 HNCS、FFCS 或 LUMIX 和空间效果，在线性光中使用 Lanczos 调整为约 24MP，再编码 BT.2020/PQ 10-bit HEIF。

成片来源记录保存实际输入帧哈希和曝光、参考帧、模型与变换哈希、白平衡归属和处理状态。Speed／Balanced 的质量选择与配方一起冻结，统一固定 24MP 成片目标。

### 调色前文件与测试记录

当高级设置开启调色前原片归档（日常默认关闭）时，Balanced 快门为照片冻结一个 `rawArchiveID`。完成合成后，先在 `RAWCaptures/<ID>/balanced/` 写入 `balanced-camera.dng`、`balanced-linear.tiff`、颜色变换及源元数据；未携带 `rawArchiveID` 时不生成 `linear-camera.f32` 或调色前归档。品牌色彩、后期曝光增益与空间效果不写入这些调色前文件，调色成片照常进入相册。

合成 DNG 是三个相机颜色平面的 32 位浮点 LinearRaw，携带原拍摄白点、颜色矩阵、基准曝光、方向、实际 ISO 与曝光时间，黑白电平分别为三个通道的 0 和 1。文件已完成镜头处理，省略原始 opcode，防止再次应用。线性 TIFF 保存实际交给颜色引擎的扩展线性 sRGB 数值，以线性 sRGB ICC 标识；两份文件均保留有符号值和 HDR 范围。

`CaptureRAWStore` 先写临时目录，文件同步并记录哈希后再发布 `archive.json`；同身份重试验证并复用文件，来源冲突拒绝覆盖。原始文件存储与相册交付独立，调色失败仍保留已发布文件；高级设置支持统计并一键清理已完成的归档与样本目录。

高级设置的「记录 11 张 RAW 素材」使用 `probe` 事务，在主摄原生视角锁定曝光、ISO、焦点与白平衡，按硬件上限分组记录十一张等曝光 Bayer DNG、整数缓冲与元数据到 `F5Samples`，供离线选帧。

「记录当前场景 · Balanced」始终生成 `rawArchiveID`，完成四帧采集、合成与原片归档，不调用品牌调色、HEIF 编码、回看或 Photos，也不请求相册权限。Bayer 输入先保存到同组的 `bayer-inputs/<事务 ID>/`；合成或归档失败时保留输入，成功后按原片保留开关决定是否清理。整个记录期间禁止重复启动测试或普通快门。

### 恢复与归档

`F5CaptureFormat` 实现格式载荷、来源编解码、复制、校验、恢复和渲染。普通拍摄按 `recoverySlot` 隔离暂存和 Journal，将输入复制到该槽受保护且排除备份的 `burst/` 目录，发布记录后返回已校验载荷并清理重复暂存。重启重新校验文件；明确放弃只清理对应范围，不要求 intent 解码成功，也不执行归档。诊断记录仅在普通队列完全空闲时启动。

系统照片图库确认保存，且冻结快照开启 `archiveF5RAW` 时，原片归档到 Documents 的 `F5Archives`。归档包含实际的一张或四张 DNG、整数缓冲、manifest、质量与颜色记录；按拍摄 ID 重复调用复用相同归档。

## 数据与版本

处理构建为 `f5-curvature-v2`，事件解码为 `f5-effective-v2`，成片色彩桥为 `f5-dng-linear-d50-baseline-v2`。格式标识为 `f5`，拍摄记录 schema 为 2；快照用 `rawArchiveID` 关联调色前文件、`recoverySlot` 标识普通拍摄槽位。`burst.json` 使用 `f5-burst-v1`，记录实际帧数；`intent.json` 保存冻结快照和已接收帧；`quality.json`、`color-transform.json` 及按需生成的相机浮点文件保存重建与颜色信息。

普通拍摄使用 `GlassCam/F5Staging/slot-0`、`slot-1` 及 `GlassCam/PendingCaptures` 下对应槽位；诊断事务使用独立暂存范围，`F5Archives` 保存用户选择保留的原片。读取时验证目录边界、字节数与 SHA-256。保留的五帧记录夹具用四张主曝光重建；`CF5` 的短帧似然检查属于独立数学参考。

## 已知限制

- Speed 和 Balanced 采集仅使用物理主摄原生视角。
- 噪声来自 DNG 元数据及共同逐相位模型，空间增益后的噪声近似使用该共同模型。
- 四帧等曝光不提供额外短曝光高光；有效细节取决于位移、噪声、运动与局部可靠度。
- FFT 尺寸的质因数限于 2、3、5、7。
- 不支持 BigTIFF、三光源 DNG、Stage3 稀疏 GainMap 或支持域以外的必需 opcode 与几何变换。
- 浮点 LinearRaw DNG 的直接预览取决于 RAW 解码器，查看调色前画面可使用同目录的线性 TIFF。
- 相机硬件锁定和手机完整流程性能由设备验收覆盖。
