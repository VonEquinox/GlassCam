# 低开销双路接缝匹配：论文、实现与本项目取舍

研究日期：2026-10-22。范围是主摄／长焦中央画面与较广镜头外围的真实视频匹配，不使用 LiDAR，不估计完整深度图。以下区分原文方法、工程推断与已经实施的内容。

后续发现：此前版本安装后用户仍反馈轻微转动黑化，离线已复现“最高相关峰的位置被误当成必要可见位移”的错误，并完成当前位置一致性检查。详见[运动不稳定诊断及 Apple 标定接口核查](MOTION_INSTABILITY_20261022.md)。该新构建未安装，手机调试已按用户要求停止。

## 与当前故障直接相关的结论

### 多深度场景不能依赖一个全局变换保证所有边缘对齐

[Zhang、Liu，Parallax-tolerant Image Stitching，CVPR 2014](https://openaccess.thecvf.com/content_cvpr_2014/html/Zhang_Parallax-tolerant_Image_Stitching_2014_CVPR_paper.html) 指出不同视点、多深度造成视差；其方法结合全局单应性、局部形变与接缝代价。论文目标是找到可拼接的区域，并非让整个重叠区都严格一致。

本项目的推断：全图配准成功不能直接作为玻璃质量分数。室内椅子、床架、门和地面可能属于不同深度；新的全图配准可能跟随另一平面。因此，在同一帧上比较新旧变换的实际接缝残差，比无条件采纳新矩阵合理。

已实施：只验证与外围区块相邻的边界；新旧候选均在当前帧验证，优先更完整的验证，接缝残差接近时保留已建立的变换（一分析像素的稳定带）。本轮没有接入论文的网格形变、接缝移动或多带融合；中央画面与固定边界契约不变。

### 亮度差、噪声和物体边界会破坏简单相关匹配

[Zabih、Woodfill，Non-parametric Local Transforms for Computing Visual Correspondence，ECCV 1994，作者原文](https://www.cs.cornell.edu/~rdz/Papers/ZW-ECCV94.pdf) 提出 rank／census，用局部亮度的相对次序描述结构，讨论物体边界混合不同像素分布时传统相关法的问题。这类变换有利于抵抗部分光度变化；它不能产生被遮挡的对应关系，平坦区的比较也会受到噪声影响。

[OpenCV 的 ECC 配准接口](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html) 提供配准前高斯滤波参数，默认尺寸为 5；这属于分析预处理，不意味着模糊最终显示图像。

本项目的离线复现：17×17 区块原来的方差门槛为平方差之和 0.012，相当于标准差约 1.64 个 8-bit 灰阶。两路摄像头各自几灰阶的无关噪声可越过门槛，但无法互相相关，导致平坦地面反复被认作“有纹理却找不到对应”。

已实施：两路分析亮度使用相同的可分离 3×3 二项式滤波，再判断纹理并匹配；显示纹理和中央预览不经过这个滤波。保留原来的色度、原始 RGB 局部外观、明显结构差异与有效几何检查。独立噪声不能认证整面无纹理墙的初始几何；真实边缘位移超过 10% 的用例继续拒绝或测出超阈值残差。

Census 尚未接入。当前已复现的噪声故障可以用上述小滤波修正，暂不增加描述子、全图代价体和维护成本。之后若捕获到混合深度区块的稳定误配，可比较带弱比较掩码的 Census 与现有归一化相关。

### 小区块、时间先验和严格验证比每帧重新求全图更适合预算

[Kroeger 等，Fast Optical Flow using Dense Inverse Search，ECCV 2016](https://arxiv.org/abs/1603.03590) 使用区块逆向搜索、多尺度聚合及后续优化；[作者实现](https://github.com/tikroeger/OF_DIS)与 [OpenCV DIS 实现](https://github.com/opencv/opencv/blob/4.x/modules/video/src/dis_flow.cpp)可供核对。OpenCV 实现包含高斯金字塔、区块均值归一化与已有位移的初始化。论文速度不能直接换算为本项目在 iPhone 上的性能。

[OpenCV 的稀疏 LK 示例](https://github.com/opencv/opencv/blob/4.x/samples/python/lk_track.py)会将匹配点反向跟踪回起点，过滤往返不一致的点。这针对误配可靠性，不会解决无纹理或真实遮挡。

本项目已采用有界的接缝区块搜索、位移提示和不同更新频率；仍是项目自身的归一化相关实现，没有导入 DIS、OpenCV 或完整稠密光流。反向校验目前列为后续针对明确误配样本的候选，不将其描述为已经实现。

## 当前证据的边界

21:24:44 的房间界面截图上下玻璃为黑；同时间段双路约 60 对／秒，底边中央分析点反复报无相关。匹配过期和黑化链路已被实时日志确认。截图不是该时刻的双路原始帧。

保存的第二对原始预览 PNG 来自 21:24:27 的桌面，早于上述房间截图。因此，噪声复现证明了代码中的一个实际缺陷，不能证明该房间失败点只受到噪声影响，也不能排除真实遮挡或混合深度。

修正后的行为已在合成已知几何、连续噪声、曝光差、遮挡、移动中央物体和两组已有 PNG 上离线检查。用户断开手机期间没有继续操作手机；之后用户重新连接并请求安装，已完成覆盖安装与正常启动，未执行新的真机视觉测试。新构建的设备观感仍需后续自然使用证据。数值及构建记录见[稳定性报告](PERIPHERAL_STABILITY_20261022.md)和[结构化验证](../validation/peripheral-stability-20261022.json)。
