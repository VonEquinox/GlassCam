# iPhone ANE 与 GPU TensorOps 实测

2026-10-18。**本次候选均未采用：完整处理更慢，最终 HDR 成片也未达到既定误差预算。** 已确认小图颜色模型在 Apple Neural Engine 上执行，GPU TensorOps 的实际执行也已记录。独立 GPU Neural Accelerators 利用率和完整照片的附加硬件跟踪有明确限制，见下文。

## 设备、范围与样本

- 连接的 iPhone 18 Pro Max（iPhone19,7／A20 Pro），iOS 27.0.1（24A446）。Release，Swift `-O`，C++ `-O3 -fno-fast-math -ffp-contract=off -fobjc-arc`；Metal 4.0，关闭 fast-math 与 contraction。
- 替换的是 **HNCS 源矩阵／曝光**。原颜色核、gradation、锐化、HDR 恢复、RAW 渲染与 HEIF 输出继续使用生产代码。没有训练模型，没有把 FFCS 的查表核心移到 ANE。
- 输入与生产基线一致：6048×8064 DNG，49,513,537 字节，SHA-256 `4bd1990df9893381b89797d1e761925973c0c840c3cd47dce758635c7502929e`；24MP 输出 4242×5656，48MP 输出 6048×8064。
- 配方：HNCS Standard、L* 工作空间、−0.05 EV。矩阵来自该 RAW 的白平衡，运行时对照 C++ 上下文，所有矩阵／曝光差值为 0。
- 6 条完整路线 × 2 个尺寸 ×（1 次预热＋3 次正式计时）＝**48 个 HEIF，36 次正式计时**。额外诊断／跟踪尝试单独保存，不进入统计。
- 正式样本全部前台运行、低电量模式关闭，开始／结束及 RAW 条带中采样的系统热状态均为 nominal。每次至少间隔 5 秒；遇到非 nominal 的等待上限为 180 秒。
- **计时包含 RAW 保留、完整导出和最终 HEIF 回看；排除相机采集、Photos 保存、并行取景、输入传输及结果校验。模型／GPU 管线准备在循环外，加载与编译成本单独保存在原始记录。**

## 完整导出结果

单位为秒；中位数后为 3 次正式样本的最小—最大。变化百分比相对本批次原生产 CPU 基线。

| 路线 | 24MP | 48MP | 48MP 耗时变化 |
|---|---:|---:|---:|
| 原生产 CPU 色彩核 | **3.872**（3.867–3.889） | **3.994**（3.993–4.004） | +0.00% |
| Core ML FP32，计划 CPU | **3.923**（3.920–3.931） | **4.049**（4.048–4.050） | +1.38% |
| Core ML FP16／16 通道，CPU-only 对照 | **4.115**（4.114–4.116） | **4.246**（4.245–4.261） | +6.32% |
| Core ML FP16／16 通道，允许 CPU＋ANE | **4.203**（4.201–4.207） | **4.322**（4.322–4.336） | +8.21% |
| GPU TensorOps FP32／小块 | **3.958**（3.957–3.961） | **4.064**（4.063–4.072） | +1.76% |
| GPU TensorOps FP16／小块 | **3.944**（3.938–3.948） | **4.057**（4.052–4.060） | +1.59% |

相同的 16 通道 FP16 模型，48MP CPU-only 为 4.246 秒，CPU＋ANE 配置为 4.322 秒，后者仍慢约 **1.78%**。因此相对原程序的约 8% 损失，包含了模型表示、补齐通道与框架调用成本，不能全部归因于 ANE 硬件。
CPU 基线的全部 8 个成片与上一轮普通生产版手机导出的文件逐字节一致。每条路线、每个尺寸的 4 次输出也各自逐字节一致；传回电脑后的所有 SHA-256 已核对。

## 实际执行位置

**ANE：**首先测了 3 通道 RGB 矩阵，FP32／FP16 的计算计划均优先 CPU。随后把同一矩阵嵌入 16×16 权重，额外 13 个输入通道填零，只取前三个输出通道。此 FP16 模型的计算计划选择 ANE。
Core AI 跟踪的 `ane-hw-intervals` 中，有 **46 条**明确命名为 `standard-small-padded16_…_main__Op0_AneInference Prediction` 的硬件执行记录，与该小图阶段的 5 次准备、40 次点处理及 1 次完整数值导出对应。独立卷积对照也有带模型名的 ANE 执行记录。这里有硬件事件，依据不限于计算计划。
**整图跟踪限制：**完整 RAW 导出的 16 通道模型同样记录了 ANE 计算计划，每张图实际调用模型 126 次；但追加整图 Instruments 跟踪时，多次出现“找不到进程”或等待设备启动超时。没有把小图硬件事件当成整图逐次硬件执行的直接证据。相关失败日志完整保留。
**GPU Neural Accelerators 路径：**实际编译并执行 MPP TensorOps `matmul2d`，覆盖 FP32／FP16、64×32／4 SIMD groups 与 64×8／1 SIMD group 两种分块，并以普通 Metal 矩阵 shader 作局部对照。Metal System Trace 记录了 GlassCam（PID 5719）在 A20 Pro 上的 TensorOps 命令执行区间和对应 shader，应用中也记录了非零 GPU 起止时间。
**独立 GPU NA 计数限制：**本次公开 counter sets 只有 `GPUTimestamp`，Metal 跟踪的 `gpu-counter-info` 没有数据行，名为 `GPU Counters` 的附加 instrument 在本机不可用。因此能确认 TensorOps 在 GPU 上执行，不能给出独立 GPU Neural Accelerators 的利用率或把全部 GPU 时间算成其专属时间。

## 为什么没有变快

48MP 正式样本的分段中位数：

| 路线 | 颜色入口总计 | 外部布局／输入准备 | Core ML 预测或 Metal 提交等待 | 输出重排 | 剩余 CPU 颜色处理 |
|---|---:|---:|---:|---:|---:|
| 原生产 CPU 色彩核 | 0.641 | 0.000 | 0.000 | 0.000 | 0.000 |
| Core ML FP32，计划 CPU | 0.664 | 0.012 | 0.036 | 0.009 | 0.601 |
| Core ML FP16／16 通道，CPU-only 对照 | 0.875 | 0.044 | 0.207 | 0.013 | 0.603 |
| Core ML FP16／16 通道，允许 CPU＋ANE | 0.972 | 0.044 | 0.301 | 0.016 | 0.604 |
| GPU TensorOps FP32／小块 | 0.732 | 0.013 | 0.109 | 0.000 | 0.602 |
| GPU TensorOps FP16／小块 | 0.708 | 0.011 | 0.088 | 0.000 | 0.603 |

原生产颜色入口约 0.641 秒，而各候选仍留下约 0.60 秒的 CPU 颜色工作。这里只移走小矩阵，保留了多数处理。16 通道模型增加额外计算、存储和转换；相同模型的 CPU-only 对照已经体现了这部分成本。
TensorOps FP16 的 126 次 GPU 命令时间累计约 **0.018 秒**，但 CPU 提交并等待累计约 **0.088 秒**，另有输入准备与约 0.60 秒的 CPU 后续计算。GPU 时间包含在提交／等待区间内，两者不能相加。以上都是具体实现的墙钟／命令时间，不是芯片理论峰值或独立 NA 算力。

## 精度结果

继续使用实验前已有预算：HDR ΔEITP 均值≤0.1、P95≤0.25、P99≤0.5、最大≤1.0，且不增加裁剪；预算没有因失败而放宽。
合成测试覆盖 512×256 的中性／暗部渐变、原色、肤色方向、量化边界、随机值及 HDR 增益。两种预设共 34 个颜色配置，另有 4 个卷积对照。FP32 通过该小图筛查；FP16 和对齐到 16 通道的 FP16 均失败，Standard 最大 ΔEITP 约 22.2。
随后将真实 RAW 的最终 HEIF 统一解码到 BT.2020/PQ Float32，比较完整图像。结果如下：

| 候选 | 24MP：均值／最大 ΔEITP | 48MP：均值／最大 ΔEITP | 既定预算 |
|---|---:|---:|---|
| Core ML FP32，计划 CPU | 0.694／27.262 | 0.514／23.204 | 未通过 |
| Core ML FP16／16 通道，CPU-only 对照 | 1.039／25.445 | 0.964／25.753 | 未通过 |
| Core ML FP16／16 通道，允许 CPU＋ANE | 1.044／26.341 | 0.973／22.182 | 未通过 |
| GPU TensorOps FP32／小块 | 0.694／27.262 | 0.514／23.204 | 未通过 |
| GPU TensorOps FP16／小块 | 1.025／26.271 | 0.954／21.751 | 未通过 |

FP32 的小图通过没有保证完整成片通过。本次手机试验没有进一步分离最终误差具体在哪个后处理或编码环节被放大；只按最终成片的实测结果拒绝候选。每组代表文件还由 ffprobe 确认 HEVC 10-bit、PQ 与 BT.2020 primaries。

## 结论与交付

- 当前这类源矩阵改写没有改善手机完整处理速度，且均未通过最终 HDR 精度预算。全部候选保留为研究工具，**普通 Release 已重新安装并启动，未启用这些后端**。
- 本结论针对当前 HNCS 源矩阵／曝光和保留 CPU 后处理的实现，不是对所有图像神经网络的结论。FFCS 的主要查表成本没有在此移植，功耗和持续拍摄也未测量。
- 首轮测试桥未开启 ARC 导致的崩溃已修复；另清除了逐像素 Objective-C 属性访问造成的额外测试开销。清理前后共有的 24 组输出逐字节一致。失败、旧探针和跟踪尝试均单列，未混入最终计时。
