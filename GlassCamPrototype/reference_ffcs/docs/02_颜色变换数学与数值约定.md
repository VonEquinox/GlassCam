# 颜色变换数学与数值约定

本说明的常量和公式对应交付的 color.py 与 pipeline.py。完整矩阵和实现可直接从源码索引阅读。重建时保持夹取时机、计算顺序和领域转换，而不只套用名称相同的通用算子。

## 1. 夹取、归一化和传递函数

`clip(x)=min(1,max(0,x))`，颜色输出 RGB 三通道均独立夹取。通用 clamp 可接受自定义上下界。整数 RGB8 输入除以 255，RGB16 除以 65535，浮点单通道输入先夹取并复制到 RGB。

sRGB 解码先 clip，随后 `D(x)=x/12.92`（x<=0.04045），否则 `((x+0.055)/1.055)^2.4`。编码先 clip，随后 `E(x)=12.92*x`（x<=0.0031308），否则 `1.055*x^(1/2.4)-0.055`。每个通道单独处理。RGB8 灰 128 的线性值约 0.21586050011389926，不是 128/255 本身。

`input_is_linear=True` 直接绕过 D。apply_path 的传感器 RAW 分支目前不会自动将这个选项切换为 True，所以默认配置会对传感器线性结果再次执行 D；这是当前实现的一部分，复现既有行为必须保留。想以线性输入运行可以直接设置配置，但得到的是另一组结果。

## 2. 3×3 矩阵

列向量约定：`out_i=clip(sum_j M[i][j]*rgb_j)`。矩阵按行保存，不能转置。encoded 仅 M_sim；linear 先 M_camera 再 M_sim，夹取发生在两次矩阵运算各自之后。相机与模型全部常量在参数文档，LUT 头矩阵在资产文档。

## 3. 三线性插值

标准坐标 x=clip(R)*(N-1)、y=clip(G)*(N-1)、z=clip(B)*(N-1)。下界 floor，上界 min(floor+1,N-1)，比例 fx=x-floor(x)，fy、fz 类同。平坦索引为 `z*N*N+y*N+x`，x 变化最快。

对每个输出通道按下列顺序：

```text
a0 = c000*(1-fx) + c100*fx
b0 = c010*(1-fx) + c110*fx
c0 = a0*(1-fy) + b0*fy
a1 = c001*(1-fx) + c101*fx
b1 = c011*(1-fx) + c111*fx
c1 = a1*(1-fy) + b1*fy
out = clip(c0*(1-fz) + c1*fz)
```

代码支持嵌套 `lut[z][y][x]` 和平坦数组；通过尝试三次索引并捕获 TypeError/IndexError 判别。内置 PackedLUT 用平坦索引；普通每节点三个数的 cube 表也会落入平坦路径。

内置 axis_order=BGR，故输入 RGB 在进入插值前交换为 (B,G,R)。channel_order=BGR 时再交换输出首尾；flags&1 为真时输出已经是 RGB，不交换。轴方向和输出通道方向是两个独立选项，不能一并忽略。

## 4. sigma 与解析映射

sigma 先限制 [0.05,8]；当 abs(sigma-1)<=1e-7 时结果不变，否则逐通道执行 `clip(0.5+tanh((v-0.5)*sigma)/(2*tanh(0.5*sigma)))`。此变换发生在 LUT/解析映射结果之后，不是邻域高斯滤波，也不改变节点索引。

没有 LUT 时直接运行解析函数，不会真的创建默认的 17³ 表。先以 0.5 为枢轴计算 `(v-0.5)*contrast+0.5`；然后 `clip(v+shadow_lift*(1-v)-highlight_rolloff*max(0,v-0.72)^2)`。将得到的 RGB 转 HSV，H 加 hue_shift 并模 1，S=clip(S*saturation)，V 保留，再转 RGB 并 clip。

HSV 取 hi=max(R,G,B)、lo=min、d=hi-lo；d=0 时 H=0；否则按最大通道选择 `(G-B)/d mod 6`、`(B-R)/d+2` 或 `(R-G)/d+4`，最后除以 6。S=0（hi=0）或 d/hi。HSV 返回按六区间的 p/q/t 标准排列，具体分支在源码中完整列出。

解析映射已经使用 contrast/saturation/hue/toe/shoulder，后续 Lab 和 tone 仍会使用其中参数。**必须保留重复作用**，不能因主观认为重复而删掉。encoded 内置表也仍接受后续 Lab、tone、grain、sharpen，不是查表结果直接输出。

## 5. CIELAB

先 D 解码，再按下述 D65 RGB→XYZ 矩阵相乘；这里 _mul3 不夹取 XYZ：

```text
[0.4124564 0.3575761 0.1804375]
[0.2126729 0.7151522 0.0721750]
[0.0193339 0.1191920 0.9503041]
```

参考白 W=(0.95047,1,1.08883)。δ=6/29，f(t)=t^(1/3)（t>δ³）或 t/(3δ²)+4/29。令 X'=f(X/Wx)、Y'=f(Y/Wy)、Z'=f(Z/Wz)，L=116Y'-16，a=500(X'-Y')，b=200(Y'-Z')。

反变换 fy=(L+16)/116、fx=fy+a/500、fz=fy-b/200；f⁻¹(t)=t³（t>δ）或 3δ²(t-4/29)。XYZ=W*f⁻¹，再乘：

```text
[ 3.2404542 -1.5371385 -0.4985314]
[-0.9692660  1.8760108  0.0415560]
[ 0.0556434 -0.2040259  1.0572252]
```

最后 E 编码并 clip。adjust_lab 在此基础上令 C=hypot(a,b)*saturation，h=atan2(b,a)+2π*hue_shift，L'=clip(50+(L-50)*contrast+lightness,0,100)，a'=C*cos(h)、b'=C*sin(h)。Pipeline 的 contrast 固定 1、lightness 默认 0，只有模型 saturation/hue_shift 参与。

## 6. OKLab UCS

rgb_to_ucs 先 sRGB 解码，再乘 LMS 矩阵：

```text
[0.4122214708 0.5363325363 0.0514459929]
[0.2119034982 0.6806995451 0.1073969566]
[0.0883024619 0.2817188376 0.6299787005]
```

逐分量取带符号立方根，再乘：

```text
[0.2104542553  0.7936177850 -0.0040720468]
[1.9779984951 -2.4285922050  0.4505937099]
[0.0259040371  0.7827717662 -0.8086757660]
```

反变换先 `l0=L+0.3963377774*a+0.2158037573*b`、`m0=L-0.1055613458*a-0.0638541728*b`、`s0=L-0.0894841775*a-1.2914855480*b`，各自立方，再乘：

```text
[ 4.0767416621 -3.3077115913  0.2309699292]
[-1.2684380046  2.6097574011 -0.3413193965]
[-0.0041960863 -0.7034186147  1.7076147010]
```

E 编码并 clip。adjust_ucs 类似 Lab 极坐标调节，但 L 枢轴 0.5、不额外限制 L。Pipeline 实际调用 contrast=1、saturation=1、hue_shift=0，仍执行完整往返，存在很小的浮点误差；重建时不能直接删去。

## 7. 黑白与棕褐分支

仅 `lut_domain!='encoded'` 且 (acros 或 saturation==0 或 sepia) 时在 lab_ucs 阶段追加单色处理。灰值=clip(wR*R+wG*G+wB*B)，普通 w=(0.2126,0.7152,0.0722)，+G=(0.20,0.68,0.12)，+R=(0.62,0.26,0.12)，+Ye=(0.42,0.48,0.10)。sepia 输出 clip(y*1.04,y*0.88,y*0.68)，其余三个通道均 y。

滤镜模型保留 saturation=0，所以线性解析分支在 Lab 已消除色度，后续滤镜权重效果会受到此顺序影响。encoded 黑白表不走该附加处理，但 grain 的 acros/saturation 判断仍会输出同值 RGB。这是实际代码顺序，不能按滤镜名称自行补入不同处理。

## 8. 色调曲线

每通道先 clip(x)，`y=0.5+(x-0.5)*max(0.05,contrast)`；toe 非零时 `y+=toe*(1-y)*(0.18-0.18*y)`；shoulder 非零时 `y-=shoulder*y*y*0.22`；最后 clip。shoulder 使用经过 toe 后的 y；不能把两项都用初始 y 计算。

## 9. AdobeRGB 输出

sRGB 输出直接用 sharpen_pixels。其他 API 字符串都会进入 srgb_to_adobe_rgb，CLI 只允许 sRGB/AdobeRGB。

sRGB 经 D→XYZ 后乘 XYZ→AdobeRGB：

```text
[ 2.0413690 -0.5649464 -0.3446944]
[-0.9692660  1.8760108  0.0415560]
[ 0.0134474 -0.1183897  1.0154096]
```

逐通道 `clip(max(0,v)^(1/2.19921875))`。返回 sRGB 的辅助函数先 `clip(v)^2.19921875`，乘 AdobeRGB→XYZ：

```text
[0.5766690 0.1855580 0.1882290]
[0.2973450 0.6273640 0.0752910]
[0.0270310 0.0706890 0.9913380]
```

再乘 XYZ→sRGB，E 编码。输出 ICC 是标签；这些像素转换由上述显式公式完成，没有额外的输入 ICC 变换或白点适配。
