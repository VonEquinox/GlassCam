# 颗粒、锐化与图像 IO

## 1. 确定性颗粒

颗粒不使用随机数生成器状态。细粒函数：

```text
n = (x*374761393 + y*668265263 + seed*69069) & 0xFFFFFFFF
n = ((n ^ (n >> 13))*1274126177) & 0xFFFFFFFF
n = n ^ (n >> 16)
noise = n/4294967295.0*2 - 1
```

实现整数溢出需在前两步显式保留 32 位；右移是无符号值逻辑右移。即便 seed 为负，经位掩码后也进入无符号域。hash 输出范围 [-1,1]。

粗粒来自缩小网格的 value noise。先 size=max(0.25,grain_size)，调用位置 `int(x/size),int(y/size)`，粗网格宽=max(1,int(width/size))、高类同。smooth_noise 内部 scale=max(1,width*0.008)，gx=int(x/scale)、gy=int(y/scale)，fx/fy 是分数；用相邻四个 hash 值双线性混合，hash 的 seed+17。注意 smooth_noise 的 height 参数没有参与实际 scale 计算。

n=0.72*fine+0.28*coarse；strength=grain_strength*0.035；编码域亮度 lum=0.2126R+0.7152G+0.0722B；exposure=0.35+0.9*sqrt(max(0,lum*(1-0.45*lum)))；delta=n*strength*exposure。

acros 或 saturation==0 时，g=clip(grayscale(rgb)+delta)，输出 (g,g,g)。否则 c=n*strength*clip(grain_chroma)*0.45，输出 `(clip(R+delta+c),clip(G+delta),clip(B+delta-c))`。grain_strength<=0 时直接返回输入。图像尺寸和颗粒 size 都会影响粗粒布局；seed 相同而尺寸改变不代表相同颗粒。

## 2. 两个锐化函数的差异

Pipeline 使用 **apply_sharpen_pixels**，amount<=0 时仅复制输入。否则 strength=clip(amount,0,3)*0.35，对每点计算图像边缘截断的 3×3 邻域均值（包含中心），输出 clip(center+strength*(center-blur))。radius 参数虽被接收，但当前浮点实现未使用，不应在重建时引入半径相关核。

单独的 apply_sharpen 接收 Pillow 图像，调用 UnsharpMask(radius=max(0.1,radius),percent=int(clip(amount*100,1,500)),threshold=1)。这不是 Pipeline 主路径，不能用它替代浮点均值锐化，否则 16-bit 结果和边缘行为不同。

## 3. 图像读取与精度

load_image 用 Pillow 打开、EXIF 转向；I;16/I/F 单通道模式保留，否则转 RGB。load_pixels 对 .tif/.tiff 优先尝试自定义 read_tiff16_pixels；成功时忽略 Pillow 预览数值，使用原 16-bit 样本。

自定义 TIFF 读取器支持传统 TIFF magic=42 和小端 II/大端 MM，读取首 IFD 的 tags，要求 BitsPerSample=[16,16,16]、Compression=1、SamplesPerPixel=3 和 strip offset；按 strips 拼接样本并除以 65535。它并未全面核验 PlanarConfiguration、PhotometricInterpretation、方向等所有标签；适用可靠范围是 FFCS 自己的非压缩连续 RGB16 文件。该路径没有 EXIF 转向、没有输入 ICC 转换。压缩/平铺或其他复杂 TIFF 回到 Pillow；RGB16 经 Pillow 转 RGB 可能降为 8-bit，不能笼统声称支持所有 TIFF16 的无损读入。

I;16 除以 65535；I 模式整数先限制 0..65535 后除以 65535；F 模式限制 0..1；其他 RGB8 除以 255。Alpha 在转 RGB 时被移除，不合成指定背景。输入 ICC 被忽略，常规颜色流程假设 sRGB 编码输入；若源图是其他空间，应先由调用者转换。

## 4. 预览与量化

image_from_pixels 无论 bits<=8 还是 bits>8 都产生 8-bit RGB Pillow 图：q8=round(clip(v)*255)。这是预览，不代表 pixels/stage_pixels 的精度。Python round 对精确半整数采用最近偶数，跨语言应统一策略。

save_image：TIFF 且 bits>8 且提供 pixels 时调用自定义 writer；JPEG 转 RGB8，quality 默认 95，未显式配置 subsampling；PNG 输出 RGB8；TIFF8 使用 Pillow LZW。JPEG/PNG 的 --bits 16 不产生 16-bit 文件。未知扩展名交给 Pillow 判断保存格式。

## 5. TIFF16 写入规格

小端经典 TIFF，Header=`II`+uint16(42)+uint32(8)。IFD 按 tag 排序，紧接 count、12 字节 entries 与 next_ifd=0。BitsPerSample 和 SampleFormat 三值数组放在偏移 `8+2+12*12+4` 与其后 6 字节，即为可选 ICC entry 预留空间；ICC 后偶数字节对齐，再写按行连续 RGB uint16，q16=round(clip(v)*65535)。

| tag | 含义 | 数值 |
|---|---|---|
| 256/257 | 宽/高 | w/h |
| 258 | 每通道位数 | [16,16,16] |
| 259 | 压缩 | 1 |
| 262 | 光度解释 | 2，RGB |
| 273 | 单 strip 偏移 | pixel_off |
| 277 | 每像素样本数 | 3 |
| 278 | RowsPerStrip | h |
| 279 | StripByteCounts | w*h*6 |
| 284 | PlanarConfiguration | 1，连续 |
| 339 | SampleFormat | [1,1,1]，无符号整数 |
| 34675 | ICC 字节 | 有配置时写入 |

writer 检查每行宽相同，不支持 BigTIFF；超大图可能超出 32 位偏移。没有自动创建输出父目录；阶段目录由 save_stages 自行创建。

## 6. ICC 标签和显示

优先读取包内匹配配置，缺失才查系统路径或 ImageCms。选择 AdobeRGB 时 `_icc_bytes` 认可 adobergb/adobe-rgb/adobergb1998 等别名；Pipeline 的像素分支只检查字符串是否等于 srgb，因此直接 API 应传规范名称，避免标签与像素转换分支不一致。

保存 metadata 的 embedded=True 不是真实探测结果；应读取实际导出文件 ICC。检查数值优先使用 TIFF16/load_pixels 或内存浮点映射；普通显示器、预览图和 JPEG 文件不适合判定严格数值相等。JPEG 文件字节受 Pillow 及其编解码库版本影响，即便输入浮点像素一致也不能保证跨环境压缩文件字节相等。
