# iPhone 生产导出分段实测

2026-10-18。在连接的 **iPhone 18 Pro Max（iPhone19,7，A20 Pro）／iOS 27.0.1（24A446）** 上完成正式批次 56 次导出：8 次尺寸预热、40 次正式计时、8 次关闭分段计时的数值对照。另有 1 次前置试运行，单独保留，不进入统计。

## 范围与构建

实测调用当前生产 `SourceImageFile → ImagePipeline.writeHEIF → ImagePipeline.load`，从内存中已有的 RAW 保留到临时文件开始，到最终 HEIF 回看解码完成。回看为 1536×2048。**不包括相机曝光／RAW 生成、保存 Photos、输入传输、App 启动、结果哈希计算；测量期间没有并行相机取景会话。不能直接当作按快门到保存完成的时间。**

- 基础代码：`4fc7a39df8736e7efe8be816f50900489fef2bde`，仅增加可选计时和构建开关控制的测试入口；颜色算法、资源、像素运算、线程策略不变。
- Xcode 27.0（27A266a），有签名的真机 Release 构建；Swift `-O`，C++ `-O3 -fno-fast-math -ffp-contract=off`。以 `devicectl --console` 启动，没有附加 LLDB。测试入口仅在 `GLASSCAM_PERFORMANCE` 编译条件下存在。
- 固定输入与此前 Mac 测量相同：6048×8064 DNG，49,513,537 字节；24MP 输出 4242×5656，48MP 输出 6048×8064。两种尺寸都执行 126 个 64 行源图条带，先处理完整源，再缩小。
- 输入 SHA-256：`4bd1990df9893381b89797d1e761925973c0c840c3cd47dce758635c7502929e`。
- 配方与 Mac 测量相同：−0.05 EV，HNCS Standard／Nature 使用 L* 工作空间；FFCS 为 XH2S PROVIA／ACROS 中性默认。Standard／Nature 没有颗粒，FFCS 没有额外颗粒／USM。白平衡从该 DNG 绑定。
- HNCS 保持最多 4 个工作线程及既有温控策略；FFCS 应用入口仍为 1 个工作线程。本次没有测试增加线程数后的加速。

## 完整时间

单位为秒。每格为 **5 次正式计时的中位数（最小—最大）**。每种配方独立启动进程，先分别预热 48MP／24MP，再做 5 轮，24MP／48MP 顺序逐轮交替；每次开始前至少等待 5 秒。没有删除慢样本，也没有用 5 次数据推算 P95。

| 配方 | 24MP | 48MP |
|---|---:|---:|
| HNCS Standard | **3.913**（3.864–3.985） | **3.989**（3.981–4.501） |
| HNCS Nature | **3.867**（3.864–3.878） | **4.004**（3.983–4.013） |
| FFCS PROVIA | **5.032**（5.028–5.046） | **5.135**（5.129–5.139） |
| FFCS ACROS | **5.030**（5.019–5.172） | **5.143**（5.132–5.158） |

## 分段时间

以下同样为每段在 5 次正式样本中的中位数；单位为秒。先对每次运行中同类条带的时间累加，再求中位数。各段独立取中位数，不必恰好相加等于完整中位数。Nature／ACROS 的逐段原始数值也保存在汇总 JSON。

| 实际处理步骤 | Standard 24MP | Standard 48MP | PROVIA 24MP | PROVIA 48MP |
|---|---:|---:|---:|---:|
| 保留 RAW 文件 | 0.033 | 0.041 | 0.041 | 0.042 |
| 白平衡／RAW 参数、输入图与上下文初始化 | 0.075 | 0.073 | 0.076 | 0.075 |
| RAW 渲染：126 次 Core Image 调用累计 | 1.186 | 1.186 | 1.205 | 1.206 |
| 条带缓冲分配、RGBA→RGB、HDR 幅值分离 | 0.426 | 0.426 | 0.426 | 0.426 |
| 颜色引擎入口 | 0.641 | 0.644 | 2.617 | 2.616 |
| HNCS 全图原生锐化，含内部读写 | 0.635 | 0.636 | — | — |
| 后置颜色／HDR 恢复／RGBA 打包及检查 | 0.281 | 0.280 | 0.184 | 0.184 |
| 中间工作文件读写、RGBA 文件写入 | 0.176 | 0.173 | 0.069 | 0.068 |
| 像素映射与最终输出图像准备 | 0.061 | 0.061 | 0.065 | 0.065 |
| 最终 CI 求值、HEIF 编码与输出校验 | 0.183 | 0.246 | 0.181 | 0.240 |
| 导出其他开销：调度、资源释放、计时开销等 | 0.021 | 0.024 | 0.016 | 0.016 |
| HEIF 回看解码 | 0.150 | 0.198 | 0.154 | 0.195 |
| **完整总耗时** | **3.913** | **3.989** | **5.032** | **5.135** |

这里使用实际 API 调用前后的单调时钟，已经能把 RAW 渲染、颜色处理、Swift 像素转换和文件调用分开，不再用进度阈值代替独立阶段。计时边界仍有以下具体含义：

- RAW 渲染包含 Apple RAW／Core Image 输入图的延迟求值和同步读回，不能进一步宣称是纯去马赛克时间。
- 颜色引擎时间包含 Swift 桥接、上下文和缓冲处理，以及 C++ 颜色计算；没有进一步拆分每个矩阵、LUT 或 Gamma。
- HNCS 锐化是现有整图原生磁盘接口的完整调用，内部 I/O 归在该段。外层文件读写是 API 墙钟时间，不代表物理闪存耗时；延迟回写或后续缺页可落到其他段。
- Core Image 的缩放、限幅和输出色彩转换会延迟到 HEIF 写入时执行，因此该段不是纯编码器时间。
- 未归属开销单列。8 个关闭分段计时的对照验证输出一致性，每种条件仅有 1 次，不能据此精确声称计时器的开销是多少。

## 运行条件、波动和质量核验

全部 40 次正式计时的开始／结束及 RAW 条带中的热状态采样均为 `nominal`；前台运行，低电量模式关闭，USB 供电，正式批次电量报告为 80%。这只是系统热状态等级，没有测得摄氏温度。

ACROS 的额外 48MP 关闭计时对照结束时从 `nominal` 变成 `fair`；之后等待约 180 秒仍为 `fair`，完成了最后一个仅用于数值核对的 24MP 对照。这两个对照用于输出一致性核验，正式中位数由前述 40 个正常热状态的样本计算。全部状态和等待时间都已保留。

Standard 48MP 的一次正式样本为 4.501 秒，仍纳入统计。相对各段中位数，该样本增加的时间主要落在 RGBA 文件写入（约 +0.202 秒）和含内部读写的锐化调用（约 +0.247 秒）；现有数据不足以把原因进一步归为某个系统或闪存行为。ACROS 24MP 的 5.172 秒慢样本也保留。

- 正式批次 56 个输出均已从手机取回，逐一与手机生成的 SHA-256 对照一致。
- 每个配方／尺寸的 7 个输出（1 预热＋5 测量＋1 关闭计时对照）逐字节一致，共 8 组。
- 应用实际核验完整输出尺寸、ImageIO 通道深度与 HDR 色彩空间。Mac 上另用 `ffprobe` 对 8 组代表文件独立读取，确认 HEVC、`yuv420p10le`、PQ `smpte2084` 与 BT.2020 primaries；其 1024×1024 编码尺寸属于 HEIF tile，完整网格尺寸由 ImageIO 核验。
- 正式批次的进程历史峰值 RSS 最大为 2,532,704,256 字节（2.359 GiB）。它包含系统编解码器、映射页与本进程先前运行，不是单张的独立峰值，也不是 iOS `phys_footprint`。
- 测量版与普通版的有签名 Release 构建均通过，既有全源导出契约检查 5 项通过。普通 Release 已重新安装并启动，测量入口的编译条件已关闭。

## 对优化的直接意义

1. **FFCS 应优先测现有颜色入口的并行收益。** PROVIA 48MP 颜色入口约 2.616 秒，占完整时间约 51%；应用当前仍为单工作线程。这是候选方向，尚没有真机多线程加速数据。
2. **HNCS 的瓶颈分布更分散。** Standard 48MP RAW 渲染约 1.186 秒，颜色与锐化各约 0.64 秒，RGB 转换／HDR 分离约 0.43 秒。单独优化颜色内核不能消除前后处理成本。
3. **24MP 主要节省末端编码和回看。** 主体仍执行完整 48MP 的相同 126 个条带；本次完整中位数只少约 0.08–0.14 秒。
4. 本次是固定 RAW、分次等待的正常热状态测量；取景并行、真实拍摄与 Photos 保存、持续连拍后的热稳定性能和能耗仍未在本批次测量。
