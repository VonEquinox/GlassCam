# 方案A：参考布局与原生 clear Liquid Glass

2026-10-12。用户明确批准先做A：参考图布局、外围使用系统原生clear Liquid Glass，并保留现有基础双镜头对齐。A是第一轮原生视觉实验；还没有Mac/iPhone上的视觉或GPU成本测量。

## 已确认约束

- 中央完整成片矩形按真实窗口与照片比例作最大aspect-fit。不能为了控件留空而缩小、裁切、扭曲中央图像，哪怕只移动几像素来藏接缝。
- 玻璃区域严格是window减去photoRect。外围只显示真实较广镜头的预览，仍采用已有FOV映射；超广无更广镜头时允许黑色外围。
- A不增加边缘像素复制、画面拉伸、自定义接缝shader或额外blur。B的窄边复制/过渡尚未批准；只有A实际视觉验收不满足需求、且用户另行批准后才考虑。
- 系统玻璃使用`Glass.clear`。不以降低整体opacity或`.ultraThinMaterial`模拟透明玻璃；旧系统保留明确的普通透明界面，不冒称原生Liquid Glass。

## 窗口和模态控制

普通手机竖屏利用天然上下外围摆放控件；横屏/窄窗口使用实际剩余区域。若照片比例恰好占满窗口，就没有可容纳可见工具栏的外围。此时使用独立普通紧凑控制界面，提供返回无遮挡取景与真实拍摄/设置操作，不反过来缩小photoRect。控制界面是临时导航层，不将玻璃滤镜施加到中央成片区。

构图网格、选中边界、冻结指示均是预览UI，不进入ProRAW或导出图像。双摄预览→冻结→单摄.photo高分辨率拍摄→恢复的已实现状态机继续使用，关闭/取消和完成照片保留规则不变。

## 原生API与验收边界

Apple公开了[Glass.clear](https://developer.apple.com/documentation/swiftui/glass/clear)，并提示需要确保内容可读；这是系统材质变体，不是固定百分比的透明度保证。[GlassEffectContainer](https://developer.apple.com/documentation/swiftui/glasseffectcontainer)可以协调多个玻璃形状，间距影响融合，因此不能让容器融合效果跨越中央成片区。额外玻璃层叠加也应避免。

[flashMode默认off](https://developer.apple.com/documentation/avfoundation/avcapturephotosettings/flashmode)支持只读关闭状态的真实性。系统版本、辅助功能设置与背景场景都会影响最终呈现；此处没有实测原生玻璃透明程度、接缝、亮背景文字可读性、动画或耗电。不得将源码契约测试称为像素级参考图复刻或设备验收。

待真机验证：竖横屏/安全区/动态字号、整个中央区域无遮挡与完整构图、玻璃边界无向内溢出、真实多镜头接缝、低光/高亮可读性、紧凑窗口控制退出与重入、冻结拍摄期间状态、设置可达性、GPU帧时间和热稳态。
