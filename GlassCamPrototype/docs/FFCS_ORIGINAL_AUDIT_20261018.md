# FFCS 对原始 SILKYPIX 的独立审计

2026-10-18。参照对象是 RAW FILE CONVERTER EX 3.0 powered by SILKYPIX 8.1.20.0 的原始 x86_64 核心库，不是富士相机固件。FFCS 0.2 交付程序与 GlassCam 都是另行实现的包装流水线。原版库 SHA-256 为 `a0bdc416748549eada3086c4fa92015912ca6acc4b07b721f38bd2aa95af61b9`，使用既有展开文件和 Rosetta，没有安装程序或操作手机。

## 已分析且已验证

[反编译工具](../tools/decompile_ffcs_stages.py)实际运行 radare2／r2ghidra `pdg`，读取原版映射构造、V1/V2 文件头、gamma 表、默认分派、三线性、正态分布、sigma、Lab/sRGB 原语，以及上游 3DCM 滤镜。复杂类型推断与警告保留。数值验证由[原生适配器](../tools/native_ffcs_audit.cpp)和[独立比较工具](../tools/audit_ffcs_original.py)完成，不以反编译文本本身充当正确性证明。

共核验 **50 个原始资源，每表 29,010 个输入，总计 1,450,500 像素**。输入包含 20,001 级中性灰、17³ 网格和 4,096 个固定随机值。

| 项目 | 结果 |
|---|---|
| V1／V2 gamma 解析 | 与原版 getter 一致；V1 `/100`，V2 `/1024` |
| 输入、输出 gamma 表 | 2,000,100 个表项，全部一致 |
| 显式 gamma 三线性入口 | 独立固定点实现对原版 4,351,500 通道，最大差 0 |
| 新进程默认的 encoded 分派 | 独立固定点实现对原版 4,351,500 通道，最大差 0 |
| 原版对象的矩阵改为单位矩阵 | 两种映射入口的全部输出均不变 |
| 正态分布分支 | 原版 sigma 0.5／1／2 均可调用，其输出与三线性不同；未把它们声称为已移植 |

完整结果、最差输入、原始资源和当前源码摘要见 [机器报告](../validation/ffcs-original-20261018.json)。原版调用后的 LUT、gamma 表和输入输出留在报告所列的外部证据目录，可重复运行比较。

### 输入域和插值不能混用

原始 LUT 为带边界节点的 64³／80³ BGR16 数据，实际插值区间分别为 62／78。原版接口的工作量程为 20,000。

`TransFormTrilinear`（`0x784968`）使用输入 gamma 表取得 8 位小数坐标，B/G 插值后右移 8 位，随后 R 插值右移 16 位，再查输出 gamma 表。不能用普通浮点三线性替代其量化顺序。

在本次新进程中，`m_b3DMappingNormalDistribution` 为 0。此时 `TransForm`（`0x782bec`）走 encoded 分支：坐标由整数比例得到，不查 gamma 表；B/G 插值后右移 16 位，R 后右移 8 位。两者即使接受相同的 UInt16 数字，数值域也不同，不能直接比较并归因于颜色错误。GUI 或其偏好可能启用其他分支，本报告不推定 GUI 默认等同于新进程的全局初值。

### 更正旧文档的矩阵说法

原始交付 `REFERENCE_ANALYSIS.md` 声称“三线性入口已包含矩阵处理”，这个说法不成立。`ReadMappingData` 解析矩阵但未将它烘入 LUT；`TransFormTrilinear` 和本次默认 `TransForm` 都不读取它。直接改变原版对象矩阵后，50 表输出仍逐位相同。

上游 `IslEISFilter3DCM::FilteringLine`（`0x92af56`）另有整数矩阵和限幅阶段，然后调用映射。`Set3DMapping` 还把头部字段拷到该滤镜的 Q8 倍率；不能仅因原探针称它为 `id` 就忽略它在调用者里的作用。矩阵的最终来源与每图 RAW/工作空间绑定尚未建立，不能把该矩阵直接当成 Apple linear-sRGB 的补偿矩阵。

现有包装资产的单位矩阵应理解为“映射分量的输入约定”，不能解释成已包含完整原版输入变换。原始交付快照保留不改；这项审计更正其证据范围，没有凭猜测向生产流程再乘一个矩阵。

## 当前包装 LUT 的已知近似

FFCS `.lutz` 是从原版映射再次采样得到的网格，GlassCam 对它执行浮点插值。它能与 FFCS 0.2 参考程序一致，但不能逐位复现原版固定点入口。

在两者输出均解释为 sRGB、统一 D65 XYZ/Lab 的条件下，本次对原版 encoded 分派得到以下 ΔE00。这衡量该映射分量的数值差，不是原厂 ICC、真实相机或绝对色准测量。

| 表 | 均值 | P95 | P99 | 最大值 |
|---|---:|---:|---:|---:|
| XH2S PROVIA | 0.111675 | 0.465700 | 0.771568 | 1.520327 |
| XH2S ACROS | 0.018931 | 0.072672 | 0.104550 | 0.578401 |
| XA3 VELVIA | 0.094012 | 0.393838 | 0.713948 | 2.067012 |
| XH2S PRO NEG. HI | 0.124697 | 0.513222 | 1.061430 | 3.502497 |
| GFX100II REALA ACE | 0.078112 | 0.273752 | 0.415167 | 1.478215 |

50 表等样本汇总均值为 0.058517；最高单表均值为 XH2S VELVIA 的 0.127700。旧报告的 2,000 个随机输入、显式 gamma 入口及最高均值约 0.054 是另一组条件，不能与本次最大值相互替代。最差点包括中性灰与网格样本，不能据均值低就宣称所有颜色差异不可见。

## 已实现但原厂依据不足

- 当前 C++ 支持 20 个稳定外观编号与五个表族的实际可用组合；缺失的 GFX100S/II 外观仍按交付规则使用 GFX100 表，不能当成对应机型专用标定。
- 默认关闭解析叠加，保持表中固有的黑白／滤色／棕褐变换。显式叠加的 Lab/OKLab、tone、颗粒和 Gaussian USM 来自第三方研究配方，缺少原版整链等价证据。
- App 的曝光在 linear-sRGB 输入上施加，随后按研究配方转换和取样；没有证据把它解释为完整 SILKYPIX RAW/WB/曝光处理。
- 原版 sigma 平滑与研究配方的参数不是同一个可互换实现；本轮没有扩展 App 的参数承诺。

## 尚未完成或缺少依据

原版 RAW、WB、自动曝光、3DCM 输入矩阵来源及最终 ICC 的整图对照仍缺少真实富士 RAW 和配套原版成片。现有 `.raf` 文件是合成解析夹具，不能当作相机样本。没有任何结论证明富士机内 JPEG 等价。

此次没有发现 GlassCam 对已声明 FFCS 0.2 默认数学顺序的新移植错误；不为制造修复而改写预期结果。后续严格加速必须对当前输出逐位一致，并另列这里已经量化的原版残差；近似加速也不能把残差藏进平均值。

复现：先运行 `decompile_ffcs_stages.py --library /absolute/path/to/SILKYPIX8 --output-dir /external/readable-c`，再运行 `audit_ffcs_original.py --library /absolute/path/to/SILKYPIX8 --reference-root /absolute/path/to/HNCS --output-dir /external/ffcs-audit`。两个工具均锁定原版哈希。
