# 透明切换代码审查与修复 · 2026-10-25

> 本文记录较早的 v4 方案。用户随后提供反例并明确取消外围矫正，当前实现以 [直接拼接修复](DIRECT_STITCH_AND_MULTICAM_20261025.md) 为准；这里的“未知继续透明”不再是当前规则。

用户要求大部分场景能正常透明，并明确接受更多畸变。本轮据此更新显示策略：真实、及时的超广角画面优先持续显示；匹配结果用于改进对齐与柔和遮罩。未知几何仍保留为未知，不能把显示偏好写成零误差证据。

## 审查发现与处理

| 级别 | 已确认问题 | 结果及修复 |
|---|---|---|
| P1 | `PeripheralGlassView` 只上传分析所对应的旧帧，分析约 12 Hz，显示约 60 Hz；两者共用 200 ms 截止 | 旧证据晚到导致有效超广角画面无法显示。引入 `PeripheralLivePipeline`／`PeripheralLiveTextureStore`，每次上传最新相机帧；匹配保留为独立后台任务。200 ms 只限制真实显示像素年龄，不再要求显示帧同时拥有完整匹配证书。 |
| P1 | 原生接缝使用所有 tile 全部通过才能放行整侧；弱纹理、周期纹理、局部线条失败会变成全侧黑 | 保留严格测量用于诊断，显示改用每边可见误差分布、支持比例和大面积不一致比例。孤立局部错误不再遮住整侧；不确定时显示真实广角回退。 |
| P1 | 原版即使修复恢复计时，旧资源短暂过期仍会强制黑帧，且用同相机共同运动否定旧分析帧 | 实时显示使用当前像素，移除旧分析帧到当前中央帧的硬运动门。相邻小幅移动不再因为分析帧年龄而断画面。 |
| P2 | 调节容差时重置整个纹理缓存与恢复状态 | 新容差直接参与渐暗计算，资源仍使用最新有效图像；新分析随后更新。拖动滑条不会主动清空画面。 |
| P2 | 滑条只放宽匹配条件，最终 5%～10% 全黑曲线及其他独立门仍固定 | 独立显示曲线默认容忍 8% 短边可见错位，8%～20% 渐暗，随容差平方根缩放；容差 4 对应 16%～40%。它是显示偏好，不是光学畸变率或物理位移精度承诺。 |
| P2 | 开启实验实时色彩会无条件禁用外围 | 去掉该遮黑条件。外围仍是原始相机色彩加双摄亮度补偿，中央滤镜色彩可能与外围不同。 |
| P2 | 密集修正的 ROI 只按宽度留边，竖图的纵向偏移可能需要更大余量 | 改为按长边留足读取范围；实时采样还检查当前窗口、矩阵、修正强度和镜头身份。 |
| P2 | 最新分析和实际显示使用的映射可能不同，原记录只保存分析光流 | 保存真实显示模型的原始光流、强度、矩阵、颜色参数、模型源帧及当前像素帧，逐文件散列；增加 worker 排队／配准／原生检查阶段，能定位首次分析未完成的位置。 |

## 新显示路径

`当前双摄帧 → 最新超广角像素上传 → 平滑映射与颜色补偿 → 按边渐暗 → 原生 clear Liquid Glass`

后台匹配独立输出空间修正与每边观测。首次匹配尚未返回时，按实际视场比例显示超广角；收到合法结果后，单应矩阵以约 0.12 s 时间常数平滑更新。映射建议与其原始捕获时间绑定，最多保留 0.65 s；较旧空间修正逐渐减弱并回到视场映射，期间持续上传当前帧。

为避免错误修正，投影须有限、不翻折、覆盖整个当前窗口，并限制相对基础视场映射的角点偏离。矩阵变化、旋转、镜头 epoch、图像尺寸变化和 GPU 回调均验证身份。过期、缺失、失败上传和真实视场不足的资源仍不显示；不会通过扩大像素有效期冻结旧画面。

每边遮罩使用约四分之三分位的受支持可见距离，大面积不一致从边界约 30% 起作用；少量不能唯一匹配的 tile 不再作为全侧否决。明显恶化需持续约 0.25 s，随后用约 0.45 s 变暗；恢复约 0.22 s，无需重新积满整套“连续通过”门槛。真实源丢失时仍立即遮住，恢复有效源后正常淡入。

原 `PeripheralEvidence`、`PeripheralGlassPolicy`、`PeripheralTextureStore` 仍用于严格测量与历史回归比较，**不再决定实时外围图像能否上传**。离线 JSON 的旧 `staticRepeatedInput*` 字段为旧门控对照；新版结果必须读取 `livePreview`／`liveAllPanes*`。

## 验证范围

- 两批用户原始 ZIP 共 22 个静态场景，用生产 Swift 分析器、生产实时显示控制器及真实 Metal 纹理上传重放。冷启动与以记录矩阵为候选分别运行，不把候选当证书。
- 新 10 组默认容差 1.00：10 / 10 所有外围边完全打开。
- 旧 12 组默认容差 1.00：10 / 12 所有外围边完全打开；其余两组保留局部渐暗，所有 12 组都能看到全部外围区域。严格旧门控在同一记录上仍有失败，证实新的显示结果并非伪造了匹配通过。
- 另外重放 18:02／18:08 两次现场捕获，缺失分析的记录从原始 tapPair 重新计算，不假造 analysisPair。
- 专门验证连续两秒没有任何完成分析时，实际 GPU 图像仍随输入红／蓝帧改变，启动后保持透明；旧的分析身份不能冒充当前像素来源。
- 使用手机原始 180 个显示时刻、合成新鲜输入和真实 GPU 上传，启动一秒后的 121 次均完全打开。这里复用的是实际调度时间，合成输入不冒充录制视频。
- 检查短暂误差不会黑闪、持续大范围错误会渐暗、单条局部线不遮整侧、容差变化、源停止、视场不足、窗口变化、镜头 epoch 及晚到 GPU 回调。
- 原生组件与 AddressSanitizer、原始记录／ZIP／实际显示光流字节、217 项 Python 回归通过。签名 Release 已构建。
