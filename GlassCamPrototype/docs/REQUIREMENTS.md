## 最新已确认同步要求

2026-10-13：用户要求先接入新HNCS的真实预设曲线，并与新交付相关bugfix全部对齐，包括完整目标WB、方裁切和portable预设空间阶段。保留旧色彩核心/FFCS与HEIF10质量路径，新增实时代理支持须另有验证，不能复用错误cube。当前实现与完成证据统一见 [HNCS revision8](HNCS_REVISION8.md)。

## 当前源码的交互契约

- Photos / Files 保存是独立的原始 HEIF 路径。普通分享排除系统 Save to Camera Roll，避免它选中兼容 JPEG 后被误称 HEIF 保存。
- 配方尚未成功渲染时暂停保存/分享；处理失败保留可重试的已解码源，不导出陈旧效果冒充当前设置。
- 取消在条带/编解码边界生效；不可中断的 Apple 调用返回前保持 busy，避免叠加新任务。Photos 写入提交后不能撤回取消。
- 相机取消、失败、压力/中断需清除等待中的捕获并允许明确重试，不把不支持组合静默降级。

以上为源码行为，尚未通过 Apple 实机交互验收。

## 偏好推断，待样片判断

- 可能更偏好自然肤色与胶片感，而非强烈滤镜。
- 可能偏好少量完成度高的模式，而非大量控件。
- 可能更重视拍摄到成片的一致体验，而非单次离线跑分。

这些不是新增产品限制，也不阻塞当前开发；集中在实际样片比较时确认。

## 工程建议，不等同已批准范围

1. 长期保留 RAW 与配方以便非破坏重渲染；现阶段仅有本次编辑的临时源，不是完整资料库。
2. 真机按单镜头/组合逐项验收，再决定额外硬件覆盖；不永久砍掉已要求的主摄/长焦外围。
3. 保留精确参考与黄金向量，依据瓶颈选择 SIMD、线程池或 Metal；不能仅因采用 C++ 就称极限优化完成。
4. 原生 Apple RAW 解码和明确域内 C++ 核分工；ProRAW 不应被称为未处理 CFA。

## 最新确认：高精度 SDR 预览

用户要求按10bit精度计算和显示效果预览。已实现独立的 Float → RGBA16Float Metal 显示源码，替代原8位 UIImage 效果预览路径；Apple编译及实际显示仍待验证；CPU double原核不变，半精度仅可作为最终显示存储。仍为SDR，不声称屏幕面板原生10bit，也不声称浮点处理能恢复已有8bit来源丢失的信息。实时相机源位深与处理后显示位深分别说明。

用户先后置完整实时HNCS/FFCS，随后将取景候选缩小为仅色彩、无颗粒/模糊/空间效果。完整拍后算法不改；当前取景默认显示系统色彩，轻量GPU代理已接入默认关闭的实验开关，仅放行已测量的模式/固定参数；Apple执行仍未验证。源视频位深仍需诚实披露，不把拍后显示精度套用到视频输入。65³整形格点作为有明确误差的实验候选；17/33/65实测不是通用准确度保证，不能仅因显示存储超过8位就宣称代理颜色准确。见 [候选接入边界](LIVE_COLOR_PROXY_PLAN.md) 与 [GPU设计](gpu-preview-design.md)。

## 2026-10-12 方案A视觉确认

按用户参考图重排相机，外围使用系统原生Glass.clear，不用磨砂/额外blur模拟。中央完整成片矩形不得为控件缩小、裁切、变形或覆玻璃。A仅保留基础相机对齐；边缘像素复制、额外拉伸和自定义接缝过渡属于未批准的B。V1照片模式，真实网格/编辑/设置入口，闪光灯仅准确关闭状态。详见 [方案A](CLEAR_GLASS_UI.md)。
