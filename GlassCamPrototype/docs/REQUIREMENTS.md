# GlassCam：持续更新的需求与判断

更新：2026-10-11。本文是项目决策工作文档；实现状态以 TEST_STATUS.md 为准。新增对话应更新对应条目、确认级别与决策日志，不能把推断自动升级为需求。

## 已确认的方向

| 编号 | 需求 | 当前范围 |
|---|---|---|
| R1 | iPhone 原生相机/图片体验，Swift 原生界面，Liquid Glass 风格 | 第一版效果原型先做导入、前后对比、导出；不是网页替代品 |
| R2 | V1 围绕 Apple ProRAW 与已有 HNCS / FFCS 技术资产 | 当前先接可用的 HNCS；FFCS 资产尚未完整读取，未伪造替代 |
| R3 | 先跑现有处理链看效果，不先新增色卡标定 | 不把重新拍色卡作为开工条件；适配边界明确写出 |
| R4 | 图像/颜色后端使用标准 C++；重视极限优化 | 正确性、可复现测试、测量先行；不以语言名称代替性能证据 |
| R5 | 在云端编写后上传 GitHub 的新开发分支 | 保留原始技术交付分支，不合并、不发布 App |
| R6 | 需求文档持续交互维护，推断交给用户最终判断 | 本文区分确认、推断、建议、开放决定 |
| R7 | 给出独立专业意见，必要时纠正不合理假设 | 不能把“自有 ISP”“准确复现”“极限优化”等愿望写成已验证事实 |
| R8 | 手机即将到手，当前尚未进行真机验证 | 不报告 iPhone 帧率、发热、内存或功耗实测；V2 延后 |

## 待用户判断的偏好推断（不是已确认需求）

- 可能更偏好自然肤色与胶片感，而不是强烈滤镜。需要用真实照片比较判断。
- 可能更喜欢少量完成度高的模式，而不是大量可调项。第一原型只提供必要控件，不代表永久砍掉专业控制。
- 可能更重视拍摄到成片的一致体验，而不是单张离线跑分。设备到手后确认优先级。

这些推断目前不阻塞实现，也不应触发一连串问卷。下一次实际看样片时集中判断。

## 工程建议（尚未全部确认为产品要求）

1. 保存原始 RAW 与处理配方，便于非破坏重渲染；当前原型只分享处理后的 PNG，未承诺完整照片库管理。
2. 先主摄、单一路径，验证后再扩展镜头/焦段；这不是用户已批准的永久镜头限制。
3. 实时预览可使用受控近似，最终导出使用精确路径；任何近似必须有误差预算和 A/B 检验。
4. iPhone 端使用原生 RAW 解码入口；标准 C++ 负责明确域中的颜色核心。不能把系统已经处理的 ProRAW 当作未处理的传感器 CFA。
5. 保留原始数值核心为参考基准，再增加 SIMD/多线程/Metal 优化后端；不先开 fast-math。

## 下一轮真正需要决定的事

- 第一组真实样片：可先用现有照片，不必等待新手机或新色卡。
- 看到效果后判断：需要哪些外观模式、肤色/高光/饱和度优先级，以及是否进入源相机适配或标定。
- 手机到手后确认具体机型、OS、Xcode 与可用的 ProRAW 文件，再设预览响应和导出速度目标。
- FFCS 的完整素材可访问后评估接入范围。

## 版本边界

本次是能编译验证 C++ 数值核、带 iOS 项目源码的第一效果原型，不是已经装机验收的相机产品。没有实时拍摄、完整 RAW 保留/配方管理、完整 48MP 导出、FFCS 或商业分发权利清理。
