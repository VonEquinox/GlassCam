## 开始时的证据分类

**已分析且已验证：** revision 10 已测的 Phocus 普通 RGB16 工作域颜色核、film curve、gradation、亮度锐化、饱和度和灰度串联；FFCS 0.2 C++ 对交付 Python 的已列阶段和条带。所列测试有固定输入及源码摘要，不重复全量运行来代替新分析。

**已发现规则但覆盖不足：** X2D II RAW getter 的码值曝光公式和白平衡来源；Phocus 缩小半径补偿、独立 HDR 工作系数；FFCS 原版 LUT 固定点接口已有有限随机对照，但包装表有插值残差，非默认 sigma/解析调整没有原厂等价证明。

**仍需分析或缺少证据：** Phocus 完整 RAW 前处理到输出、目标 HDR/高光恢复；SILKYPIX 目标分支的独立逐阶段复核、完整 RAW/GUI 输出；基于可信基准的当前版本端到端加速。FFCS 指 RAW FILE CONVERTER EX 3.0 powered by SILKYPIX 加研究代码，不等于富士机内 JPEG。

证据入口：[Phocus revision 10](PHOCUS_REVISION10_20261018.md)、[可读分析](PHOCUS_READABLE_ANALYSIS_20261018.md)、[FFCS](FFCS.md)、[FFCS 原始参照](../reference_ffcs/implementation/REFERENCE_ANALYSIS.md)。

## 本轮进展

已生成 Phocus RAW/HDR 入口及 SILKYPIX 映射/Lab/sRGB 的可读 C。原始 SILKYPIX 8.1.20.0 库在既有只读展开目录可用，SHA-256 与 FFCS 来源报告一致，不需要补充安装器。

X2D 原版 RAW 中间值探针已跑通。发现并修正普通颜色核的有效处理增益缺口；60 组、14,155,380 通道原版比较为零差，真实 CPU RAW 区域由最大 68 码差降为零。12 组旧版单位增益输出逐位一致，新增原生黄金向量及既有完整串联回归通过。原版默认会自动启用 GPU，探针已增加明确后端选择及核验；早期自动后端结果保留并标注其边界。

详见[X2D 阶段报告](X2D_COLOR_PIPELINE_20261018.md)。HDR、最终 ICC、更多 RAW/预设/曝光/WB、FFCS 数值独立审计及加速研究仍未完成，上面的全目标清单继续有效。

### 原版导出参数工厂的纠正

`UpdateProcessParams` 更新查看器参数，不能在零初始化结构上代替原版导出默认值。保存的 `.phos` 同时含 `ImageCorrection`、`ImageDescription` 与 `OutputPreset`；新探针通过原版 `CSaveHandler::FromCorrection` 构造完整导出参数。实际 SceneCalibration intensity 从诊断初始化的 0 变为 100。原版资源由原生 `CXMLLut` 自动查找并载入，不再依赖把外部解码 plist 注册进原版对象。

同一保存 RAW、Standard 配方与 TIFF 中的 Adobe RGB ICC，自动后端 64×64 区域对历史原版 TIFF 的最大差从 794 码降至 3 码；平均绝对差 0.0423991，439/12,288 通道不同。剩余差异尚未解释，不记作零差或完整 RAW 等价。上述 68→0 的增益修复例采用较早的查看器诊断参数，仍是有效同输入颜色核检查，但不能冒充完整导出路径检查。后续将增加正式导出参数的 CPU 核前／核后对照。

正式导出参数的 CPU 核前／核后补测完成：修复前最大 74 码、11,333 通道不同，修复后 12,288 通道零差。已加入可复现的目录清单比较工具。原先一次性生成的关键导出／HDR 函数也已加入哈希锁定的反编译目标表，并重新生成 18 份可读 C 与完整清单；保留类型推断警告。

检查点 `8c877a5` 保存处理增益修复、原始向量和完整导出探针。后续扩大为 126 次原版调用；30 组普通颜色核、368,640 通道零差，最终 TIFF 比较明确区分 CPU／自动后端。共享 RAW 描述与原先构造描述的所测字段和首个区域输出相同。

HDR film curve 的增益索引、二次延伸、白点后的线性延伸和工作域比例已独立还原，40 组／7,864,320 Float32 表项逐位一致。新增生产颜色阶段 API，60 组／14,155,380 颜色通道与三个真实区域零差；六项 HDR／普通链回归通过。后面的 HDR 高光强度、gamma、空间和输出仍保留独立边界。

FFCS 独立检查已扩至全部 50 个原版资源；两种固定点映射与 gamma 表逐项零差。当前包装资产仍是再次采样的近似，有些最差样本明显超过只看均值所得的印象；正式报告将同时给出 P95／P99／最大值和默认分派的数值域。原始交付文档对矩阵已包含于三线性入口的说法需要纠正，原始参考快照不改写。

### 本轮收尾与验收

检查点 `2cf168a` 保存 HDR 颜色核与扩大的原版导出比较；`b05c222` 保存完整 SILKYPIX 映射审计。后续补做 39 个 V2 资源读取前的矩阵替换，1,131,390 输入像素及所有解压表／gamma／映射输出不变，原资源哈希不变。

HDR 后置阶段经过实际 r2ghidra C 反编译和少量取整／FMA 指令核对。初版的直接截断与错误精度混合先后产生 1 码差，失败记录均保留；修正后 42 组、8,707,059 通道为零差。原版 HDR gradation 使用独立范围生成曲线，复用 SDR 表的 Nature 区域最多差 2118 码、经过锐化最多差 2240 码；改用原版精确 HDR 表后，三个真实区域的完整颜色阶段至锐化内部区域零差。HDR 锐化另外有 293 组参数、46 组模式及 960 万表项验证。

三组新的原版 HDR 最终导出确认输入 ICC 为 Hasselblad HDR RGB（enum 8），高光默认 50／50，Standard／Nature 有效锐化 270／334。第一次新增诊断因本地符号无法通过 dlsym 查找而失败，现通过已核验 HBStorage 的导出锚点解析本地地址；失败记录保留。最终 ICC 是原版调用边界，没有记成独立复制。

严格 FFCS 采用逐码 Double 除法缓存（512 KiB／上下文）；Swift 仍用一个 worker。64 个旧新成片逐字节一致，Mac 完整耗时下降约 0.8%–2.1%。随后用最终源码重新构建，八组配方／尺寸的文件和完整 Float32 解码仍与保留结果一致；该轮只验证版本一致性，不增加性能样本。

GPU 颜色候选约快 6%–8%，但完整 HEIF 的最大 ΔEITP 达 22.93–39.46，预算失败。Standard 24MP 的编码前最大值为 0.8487，编码后为 22.9348，额外截取不改变原 HEIF 哈希，确认导出后的显著放大现象。Core ML FP16 同样失败，存在新增裁剪／渐变反转；FP32 只通过合成筛查。所有计算计划优先 CPU，不声称 ANE 实际执行。候选均保留在工具中，没有链接到 App。

最终验收：206 项 Python 检查、实际 Apple 图像/14 组 HEIF/48MP DNG、FFCS 760 次及 HNCS 106 组 ASan/UBSan、iOS Release 通用目标无签名构建通过。唯一旧源码断言已更新为检查共享配置的 iOS 文件保护分支，数值黄金值未更改。旧原厂参考、历史输出、失败实验和未完成范围保留。
