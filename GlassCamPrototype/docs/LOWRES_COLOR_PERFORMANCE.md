# 未来低分辨率实时颜色：精确 CPU 成本实测

2026-10-11。只做成本估计；实时色彩仍后置，未增加任何实时功能或改变生产核。

## 结论

- 精确 CPU 色彩并非一概不能实时：极低分辨率 HNCS 有余量；能否达到低负载仍要同时检查进程 CPU 成本，而不能只看多线程墙钟。
- 完整 FFCS 含 Lab/UCS、真实 LUT、颗粒与浮点锐化，成本显著较高。增加线程可能减少等待，却不能按比例减少总 CPU 或保证省电。
- 下面是共享 Intel 云 CPU 的实测；不是 iPhone 帧率、整机 CPU 百分比、功耗或发热预测。小样本及高波动不支持“稳定实时”的承诺。

### 具体建议

- HNCS：128×72单线程墙钟2.13ms（1.50–2.97），CPU2.13ms/帧；15/30fps分别约3.2%/6.4%单核等效。这一孤立核在本机有明显余量。
- 完整PROVIA：128×72双线程墙钟13.51ms（9.57–21.73），CPU18.60ms/帧；15/30fps约27.9%/55.8%单核等效。单线程19.89ms（15.84–23.23），CPU19.84ms/帧，也有30fps核预算余量。不能把两者小幅CPU差异当成稳定节能收益。
- 因此未来可先验证HNCS 128×72/30fps、FFCS 128×72/15fps；这只是设备实验起点，未达到用户认可的画质或整机负载标准。128×72只有9,216像素，放大显示会丢失明显细节，尤其颗粒与锐化不能视为全分辨率外观。
- 256×144 HNCS四workers请求实际串行：16.22ms p50但最大45.68ms，30fps有抖动；512×288四线程32.72ms已吃完30fps预算，且CPU需求249%单核等效，不符合“低负载”的保守目标。完整FFCS在256×144及以上本轮没有低负载30fps证据。

## 方法与边界

- 标准C++17生产API，不使用8位预览表、fast-math或新近似。HNCS输出display-linear RGBA Float32，FFCS输出display-linear RGB Float32。
- HNCS EV0 / 5500K / legacy-standard。FFCS PROVIA、ACROS均为现有完整默认look，含各自真实颗粒、锐化、tone shoulder/toe。没有实现独立DR100/200/400模式，不能把tone曲线当作其性能证据。
- 预分配输入/输出、复用上下文；固定LCG随机种子928、[0,1)线性sRGB Float32输入。是合成测试，非真实照片性能语料。
- 每配置一次预热，五轮轮换九个算法/线程配置；steady_clock测墙钟，CLOCK_PROCESS_CPUTIME_ID测整个进程所有worker的CPU时间。包含API检查、每次线程创建/join和内部scratch分配；不包含输入/输出分配、上下文建立、结果hash及oracle。
- 每个预热和测量结果FNV-1a 64-bit摘要均等于同尺寸串行生产oracle；1/2/4 workers摘要一致。摘要相同是回归证据，不代替独立数学证明。
- 128×72在其余四尺寸完成后作为独立小尺寸补充测量，仍五轮同样轮换。未隔离宿主其他任务。共享宿主波动使不同尺寸、不同worker的数字不可当作理想线性缩放曲线。尤其256×144 HNCS三个配置实走同一串行核，但不同轮次仍出现明显差异。
- 排除相机采集/RAW解码/demosaic、尺寸缩放、Swift/Core Image拷贝、Metal上传渲染、显示同步、输出编码、磁盘、Photos。没有Apple构建或iPhone实测；没有本轮12MP/48MP测量或线性外推。

环境：Intel(R) Xeon(R) Platinum 8370C CPU @ 2.80GHz；g++ (Debian 14.2.0-19) 14.2.0。可见逻辑CPU affinity=[0, 1, 2, 3, 4, 5, 6, 7, 8]；不等于独享核心。cgroup cpu.max / cpu.stat均不可读取，无法确认配额或throttling。

`-std=c++17 -O3 -ffp-contract=off -fno-fast-math -pthread`，FFCS链接`-lz`。

## 后续准入建议

先做极低分辨率、独立低频的设备实验；保持相机取景显示频率与颜色更新频率分离，只处理最新帧、不得排队累积延迟。该策略尚未实现。起点应由下表的真实CPU成本选取，不能为了帧率盲目开满workers。设备Release验证必须同时记录颜色任务墙钟p50/p95、CPU时间、整条相机显示延迟和热稳态；过预算直接丢弃旧帧或降低颜色更新频率。用户要求低负载低延迟，因此只有这些指标有余量才进入实时开发。
