## 最终开发约定（Q12 已确认）

首版面向用户自己的 iPhone。取景支持双指连续变焦、超广／主摄／原生长焦快捷按钮，以及长按连续标尺；由 iOS 根据倍率、光线和对焦自动接力，允许弱光／近摄回退。焦段范围、实际镜头和 RAW 能力由设备查询决定。

每次快门冻结构图、方向、输出选择和原有处理配方。HNCS／FFCS、HDR 和设置记忆继续保留；数码构图不能只改变取景，最终成片必须与快门时画面对应。现有色彩和约 4–5.2 秒处理基线被接受，最终另测真实拍摄到保存耗时。

| 用户选择 | 最终构图的有效像素 | 最终输出 |
|---|---|---|
| 24MP | 任意合法源尺寸 | 24MP；按需要缩小或插值放大 |
| 48MP | ≥24MP | 48MP；按需要缩小或插值放大 |
| 48MP | <24MP | 24MP；按需要插值放大 |

有效像素在变焦构图与预设额外裁切完成后计算。保持照片宽高比例，不拉伸构图；显示实际输出档位，并区分插值输出与原生有效像素。最终像素尺寸按宽高比计算并满足编码器要求，不把约数 MP 标签当作来源像素证据。

保持单张任务：当前照片保存完成后才允许拍下一张。RAW 成功落盘后持久保留任务，切后台或锁屏时停止继续提交图像处理，回到前台恢复；进程被结束后也可恢复。保存成功后清理待完成数据。

Q12 已确认：如果进程恰在相册写入途中结束，恢复出的写入结果可能未知。保留成片，提示用户核对系统相册；由用户选择确认已保存或再次保存，不自动重复写入，也不为此扩大相册读取权限。当前 PhotoKit 写入回调和占位 ID 不能提供跨进程的恰好一次承诺。

开发期间不连接手机。离线完成实现、相关回归、普通 Release 构建和交付文档，之后统一进行真机能力核验、安装、实拍、Photos 原件、变焦构图与恢复测试。安装沿用现有开发签名，提供续签步骤；按新包实际描述文件确认有效期。

## 三摄开发中必须保留的事实区分

取景倍率、等效焦距、实际物理镜头、设备变焦系数、数字裁切后的有效像素和最终输出尺寸是不同概念。中间倍率不能仅靠改变取景来实现，最终成片必须对应快门时的构图。

原流程的镜头、倍率和输出能力假设都是主摄 1×。新增连续变焦时，必须同时处理最新变焦请求、镜头切换、输出能力更新，以及快门时镜头／构图／方向的冻结。原版 RAW 色彩处理与三摄取景接力分别验收。

有效像素与插值后的文件尺寸需要分开记录和显示。24MP／48MP 是成片尺寸政策，不代表从较小源中新增真实拍摄细节。颜色处理继续使用已有经过验证的路径，输出尺寸策略的变化另行测试。

- 最终 Python 回归 206 项通过，27.348 秒。真实 Mac Core Image／Metal／HDR HEIF、恢复故障场景及 48MP DNG 测试通过。
