# 双路预览与高分辨率 ProRAW 会话切换

2026-10-12。用户已确认优先保证最终照片分辨率，允许按快门后暂时冻结取景。主摄/长焦的较广镜头仅用于外围预览，不参与成片。

## 为什么需要真正切换会话

Apple 的 MultiCam 会话采用 `inputPriority`；Apple 高分辨率拍照说明要求 `.photo` 才支持24/48MP。不能只暂停辅助预览、移除一条显示连接或降低外围分辨率，就宣称原 MultiCam 已变成支持高分辨率的普通拍照会话。此限制也不等同于所有分辨率的 ProRAW 都无法与 MultiCam 共存。

- [AVCaptureMultiCamSession](https://developer.apple.com/documentation/avfoundation/avcapturemulticamsession)
- [Implement high resolution photo capture](https://developer.apple.com/videos/play/wwdc2026/304/)（Configure a capture session 章节）

## 用户可见流程

1. 平时主摄/长焦显示真实双路视频，外围仍是预览。超广保持单摄与允许的黑色外围。
2. 按快门时固定镜头、方向、取景几何和输出选择，标明“冻结预览”。重复快门、镜头/配方/预览设置变化被阻止。
3. 保留最后已显示的中心与外围图像，真正停止并释放双摄图的摄像头所有权。串行建立同一物理镜头的普通 `.photo` 会话。
4. 在该单摄图上重新验证 ProRAW、最高支持源尺寸及构图一致性，再拍摄。48MP只有运行时确实支持才可请求，不以机型宣传值替代检测，不静默改拍12MP。
5. 完成后恢复双路预览。照片结果与预览恢复结果分开处理：已经通过didFinishCaptureFor终态成功的DNG不能因为恢复预览失败而被丢弃；仅didFinishProcessingPhoto产生的数据仍为待完成结果。恢复失败需明确状态，可重试。

## 尺寸与构图

可输出档位来自单摄 `.photo` 的实际源能力，不再由 MultiCam 的视频格式上限决定。每颗物理镜头保留用户选定的12/24/48MP后处理输出；若已保存档位当前不可用，要求明确重新选择，不能静默降档。

最终仍以最大的可用ProRAW源运行精确颜色/空间处理，之后再缩小到所选输出。视频尺寸与导出尺寸互不代替。请求尺寸只是请求，实际RAW回调必须验证；同镜头、相同比例也不足以证明相同构图，切换需要检查格式视野、缩放和方向。

## 生命周期要求

- 会话、配置、停止和捕获均由同一后台串行队列拥有，不允许两个会话同时争用摄像头。
- 旧会话观察者须移除或按会话身份排除。旧捕获回调必须在恢复动作之前核对请求身份，不能恢复到较新的镜头/前台会话之上。
- 方向变化在捕获事务期间推迟，不能改变正在拍摄的快照；恢复后再应用最新方向。
- 冻结画面有明确标识，暂停实验GPU色彩层，并保留实际原始视频层，不把黑色错误卡覆盖在冻结画面上。
- 关闭按钮在捕获/恢复期间仍可用，停止未完成事务并退出相机；它不承诺丢弃已经终态成功的照片。取消、后台、系统中断与配置失败都必须解除捕获占用并恰好完成一次。终态成功之前取消仍是取消；终态成功之后的照片与后续取消/恢复故障分别判断。

## 验证边界

云端可运行数值、源码契约与独立状态模型测试；状态模型不是Swift/AVFoundation执行。当前没有Mac/Xcode或真机，不能宣称Apple编译通过、切换延迟已测、所有镜头能拍48MP，或预览/ProRAW光学裁切完全一致。

设备验收需记录：各物理镜头的两个会话格式与实际RAW尺寸、冻结/停止/重建/捕获/恢复耗时、方向与边缘标靶、连续快门、切后台/中断/取消、恢复失败后的照片保留、峰值内存与热状态。完整照片色彩核心和HEIF10流程不因本次会话切换而修改。
