## 修复的核心判断

原生产 Swift 的三个负例已先实际复现：弱纹理和黑细线移动 24 分析像素后仍返回零误差，固定窗口之间发生遮挡也返回正常。基线结果保存在 `validation/research-answer-20261023/production-counterexamples.json`。

现在外观检查不再改写对应位移。匹配结果携带 measured / ambiguous / unobservable / budgetExceeded 等状态、经验位移区间、搜索完成状态、接缝覆盖和独立外观状态。无法判断时不再制造“可靠零位移”，也不直接制造“可靠大错位”。NaN 仅用于未知残差的诊断兼容字段，产品策略消费结构化证据。

未知不刷新上一次可靠证据的 200 ms 截止。单次低可信毛刺可以在旧证据剩余有效期内渡过；可靠大位移仍立即触发锁黑；多个分段共同确认的显著细线法向大位移也有独立保护路径，不等待其他无纹理区域到期，持续未知和资源失效仍会黑化。恢复必须由新样本连续覆盖至少 0.4 秒。5% / 10% / 8% 及 0.3 / 0.4 秒动画合同保留。

## 诊断与重跑

`GLASSCAM_PERIPHERAL_TRACE=1` 只启用元数据 trace。`GLASSCAM_PERIPHERAL_FRAME_RING=1` 单独启用分析像素事件包；正常运行二者默认关闭。不会调用相册或保存用户照片。队列中仅保留小型自有分析数据，诊断器不保留系统原始 capture buffer。

Mac 离线生产检查：

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer python3 tools/test_peripheral_glass.py
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer python3 tools/test_peripheral_glass.py --sanitize
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer python3 tools/test_peripheral_glass.py --benchmark
```

命令在 `GlassCamPrototype` 内运行。Python 回归需 NumPy、SciPy、Pillow、tifffile；本次使用专用测试 venv，没有修改项目产品依赖。ASan 使用 `detect_leaks=0`，验证越界等地址错误，不把 Apple 运行时缓存当成本轮泄漏结论。

结果目录：`validation/research-answer-20261023/`。`verification.json` 记录构建、测试和最终源码摘要，原始日志与微基准各自保存。

## 已验证的结果与限制

- 217 项 Python 回归全部通过。
- 生产 Swift 策略、匹配、几何、帧配对、独立光度、Vision/CI、异步发布、Metal 和诊断器检查通过；ASan 同样通过。
- 160 个已知零相对位移、独立噪声/曝光/共同旋转样本：可靠假大位移 0，可靠测量 0，未知 160。此项证明没有再把这些假峰当成确定大错位，**不证明这些场景会持续透明**。
- 无签名的 iOS Release 通用目标构建通过；没有安装到手机。
- 真实设备的弱纹理可用率、相机组合是否提供可用标定、端到端显示同步、Liquid Glass/EDR 最终合成、GPU/纹理失败的设备故障注入、持续热与功耗仍未验证。

Vision/CI 的单次系统调用不可被本模块抢占；返回后的过期结果会被丢弃，中央预览不等待该 worker。

经验候选区间及图像运动余量是有条件的工程模型，未做真实设备留出集上的概率覆盖率校准。全二维回退搜索和反向诊断各自使用真实可见支持；中央相机边缘外没有像素，不能将反向诊断称为观察到了不存在的支持。无纹理、周期、遮挡及模型失效仍可能无法可靠对应，当前严格策略会在期限后黑化。

本次没有借由拉长期限、强制将未知判零或模糊显示来制造“稳定透明”。未来若要允许只保证外观的透明模式，需要明确接受它与真实对应保证的差别，再独立实现和验收。
