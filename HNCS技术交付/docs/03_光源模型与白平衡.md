# 光源模型与白平衡

## 两类色温不能混用

源色温 T_S 是把 Sony 拍摄中性点放入 A/D65 characterization 模型得到的渲染坐标，用于选择两端 Sony→哈苏响应。最终工厂色温 T_H 是虚拟哈苏 WB 经另一套 camera→XYZ/Robertson 算法得到的整数，用于工厂矩阵/LUT。前者两端约 2747.59/7007.17 K，后者约 2716/7625 K。它们既不相同，也不是实际测量灯具光谱。

## 源 DCP 解析

`prepare_sony_source_profile.py` 只读 DCP 的 UniqueCameraModel、ColorMatrix1/2、CalibrationIlluminant1/2 和 CameraCalibration/AnalogBalance 等相关标签。代码验证型号 Sony ILCE-7RM5、Illuminant17/21 对应 A/D65、矩阵条件数、CameraCalibration 为单位矩阵、AnalogBalance 为 1。ColorMatrix2 与原日光 RAW 的 LibRaw `rgb_xyz_matrix[:3]` 对照。

矩阵方向是 XYZ 列向量→未白平衡相机列向量。源模型温度为 [2856,6504] K，两个 ColorMatrix 按逆温度权重插值，不插值其逆矩阵。只有白点定位使用该 DCP；没有采用它的 tone curve、ForwardMatrix、HueSatMap 或创意外观。

## 源 CCT 迭代

WB 以 G 归一化为 w，定义源中性点 n=1/w。从 T=5003 K 起：

```text
alpha = clip((1/T−1/T_high)/(1/T_low−1/T_high),0,1)
CM(T) = alpha×CM_low+(1−alpha)×CM_high
XYZ = solve(CM(T), n)
Tnew = RobertsonCCT(XYZ)
```

比较 `abs(1e6/Tnew−1e6/T)<1e−8`，最多 80 轮；不收敛或 XYZ 非正/非有限即拒绝。最后重新用收敛温度求矩阵与 XYZ。range 之外源矩阵固定到最近端点，CCT 本身仍可超出端点。得到的 source xy 用于记录，未用于额外色偏补偿。

Robertson 转换先把 XYZ 变 xy：x=X/sum，y=Y/sum；再令 `u=2x/(1.5−x+6y)`，`v=3y/(1.5−x+6y)`，这是 1960 u/v，不是 1976 u′/v′。31 行表的每行含 mired、ui、vi、slope。与各等温线算有符号距离，遇到非正距离跨越区间；按相邻距离插值 mired，再用 1e6/mired 得 Kelvin。源迭代函数返回连续浮点温度，不进行目标工厂整数舍入。

## 默认 paired 的响应与中性重建

每个标定端点有源 WB s_i、目标 WB h_i、白平衡后矩阵 M_i。拆开两端 WB 得未平衡响应：

```text
C_i = diag(1/h_i) × M_i × diag(s_i)
a = clip((1/T_S−1/T_day)/(1/T_warm−1/T_day),0,1)
C = a×C_warm+(1−a)×C_day
n_H = C×(1/s_capture)
g = n_H[G]
h_capture = g/n_H
M_capture = diag(h_capture)×C×diag(1/s_capture)/g
```

要求 n_H 所有分量为正且有限。该公式使 M_capture×[1,1,1]ᵀ=[1,1,1]ᵀ：改变 WB 不额外改变中性亮度。最终虚拟输入是 `M_capture×(SonyLinear×s_capture×source_scale×2**EV)`。

在拍摄 WB 与保存端点数组**逐元素完全相同**时，代码直接使用保存 M_i、h_i 和 gain=1，而不经过浮点往返，保证端点回归像素。近似相等不会触发这个分支。端点之外 a 固定 0 或 1，并记录 paired_range_clamped；仍用当前拍摄 WB 重建目标 WB，因而工厂 CCT 不必固定。

模型验证：schema=1/status=paired_chart_model；端点温度严格升序；每个 WB 正值；M 与 C 是有限 3×3；M 的行和为 1、det>0、cond≤20；检查 C 与上述 WB 拆分式一致。基准指纹对 matrix/source_wb/target_wb/source_scale/target_scale/target_cct、两端 RAW SHA、工厂资产文件哈希按 sorted compact JSON 做 SHA256。改变这些数值后旧 paired 被拒绝。

## 虚拟哈苏 WB→工厂 CCT/Tint

令 `F=camera_to_xyz[2]×diag(factory_wb[1])`，使用固定 flash 节点；`XYZ=F×(min(h_capture)/h_capture)`。再转 xy、1960 uv、Robertson 表。过零区间使用前/当前距离计算 f，目标 CCT 用 `int(K+.5)`，不是 Python ties-to-even round。

Tint 用插值中心与方向投影：`centre=prev_uv×f+current_uv×(1−f)`；方向为 `prev_direction×(1−f)+current_direction×f` 后单位化。这个权重顺序必须按代码保留。Tint 是内部 uv 方向偏离量，不是 UI 的整数滑块。

正常工厂 CCT 限制到 2000…10000 K。`--cct` 只覆盖工厂参数，不改变源 T_S、插值权重或已选择响应矩阵。白平衡预设也只先提供工厂 CCT，再用该 CCT 下 Tint 相对增益 q 改虚拟 h；q 归一化 G=1，重新构造 M。不会用完整预设哈苏 WB 替换 Sony 的拍摄 WB。

## 所有光源模式与 WB 选择

| 模式 | 响应和 CCT |
|---|---|
| paired | 两组实拍配对 C_i 插值；默认，使用源 DCP 估计坐标 |
| adaptive | 单日光 C 恒定；仅 wb_mode=camera 才启用 WB bridge；最终 CCT 随目标 WB |
| calibration | 固定日光 M 和 profile target_cct，当前选定 WB 仍用于源像素 |
| dual | Sony A/D50 与外部哈苏 A/D65 各自 CM，经 XYZ 得 `H_CM×inverse(S_CM)`；左乘常量残差锚定原日光响应，再按中性重建 |

dual 中锚定常量为 `C_cal×inverse(C_public(source_cal))`，独立来源之间的等价性是一项模型假设；它的暖光误差较高，所以没有成为默认。`hncs_dual_illuminant.py` 同时承担源 CCT 公共函数，默认 paired 会导入它，但不会使用 dual 的哈苏外部响应。

单图 `--wb auto` 先比较输入 SHA：若等于对应标定 RAW，采用色卡 WB；其他输入采用拍摄 WB。批处理明确传 `--wb camera`，即使输入恰好是标定 RAW 也使用拍摄 WB。`--target-reference` 对 X2D II 用单位映射，绕过 Sony bridge；工厂 CCT 是否按拍摄 WB 由 wb_mode 决定。

两端插值不能区分相同中性 WB 的不同 LED 光谱，也无法建模混合光局部变化。这里只把该限制说明为现有模型的数据边界，未用更高阶拟合替代缺失测量。
